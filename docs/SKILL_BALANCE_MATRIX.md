# 当前技能数值与公式总表

本文按 `Skills.java` 当前实际注册的技能及其服务端实现整理，用于统一平衡调整。数值为源码基础值，不包含护甲、无敌帧、其他模组事件或难度修正。

## 统一记号与 CP 规则

- `D`：玩家伤害倍率；`MCP`：玩家最大 CP；`E = MCP × 0.05%`；`A = 1 + E`：能力强度倍率；`I = 1 / (1 + 2E)`：演算强度（CP 倍率）。
- `H` / `Hmax`：目标当前生命 / 最大生命；`Htmax`：目标真实最大生命；`W`：主手武器攻击加成；`L`：动能加持冲击等级（1–6）。
- 表中 CP 均为基础值。正常的限时或永久占用实际为 `基础值 × I`。限时占用在迭代结束后归还；永久占用在关闭技能时归还。
- 基础迭代速度为每秒 1 点。思考并列演算提供 `1 + 熟练度档位×5%` 倍速；技能调试模式为 5 倍，并与其乘算。
- 每次施放产生的限时占用独立迭代，不会等待同技能的其他堆栈；任意一层完成后立即释放该层并允许再次使用。
- 最大 CP 固定以 100 为基础：当前技能的千点熟练度里程碑最多 +300，挑战进度最多 +200，能力等级里程碑累计最多 +300，脑域开发另行叠加。
- CP 归零会立即进入 200 tick（10 秒）过载并禁用技能；自我绝对控制使玩家免疫过载。
- SP 不会自然恢复，也不会因睡眠补满。进食会先按食物实际饱和度立即恢复 SP，再获得 `饱食度×10秒` 的恢复期；恢复期内每 20 tick 恢复 1 SP，多次进食只延长持续时间。
- “直接扣除”表示代码直接减少可用 CP、没有生成占用记录，因此不会按迭代机制自动归还。

## 调参时应优先确认的异常点

1. `light_shield` 与 `spatial_synergy` 直接扣可用 CP，没有占用记录；若目标是可恢复消耗，应改用统一占用 API。
2. `mining_beam`、`disintegrate`、`spacial_excision` 的方块处理没有显式检查全局方块破坏开关。
3. `vector_reflection` 的不足 CP 分支使用 `可用CP/10` 计算反射量，与足额分支的 `伤害×I` 不是同一比例。
4. `chain_fusion` 的排队目标会先在 `chainFrom` 受伤，队列到期时又受一次 10 点基础伤害，需确认是否为预期。
5. 未元甲虫的伤害来源当前标记为 `darkmatter_disassemble`，不是 `darkmatter_creation`。
6. `lightning_storm` 既手动造成 `8D`，又生成真实原版闪电；实战总伤害可能高于表内技能伤害。
7. `spacial_excision` 以“最大CP”为基础成本；当 `I>1` 时理论上可能无法支付，当前公共技能默认只会使 `I≤1`。
