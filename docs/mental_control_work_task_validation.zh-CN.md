# 精神控制工作任务：首轮实现与验证

日期：2026-10-01。对应 [设计方案](mental_control_work_task_optimization.zh-CN.md)。

## 已实现

- 新增公开 `WorkBudget`、`WorkScheduling`、`FairWorkQueue` 和 `WorkInventoryTransfer`。工作推进、扫描、候选检查、领取、建路、物流、实际动作和恢复共用服务器预算；默认软时间额度 2 ms。使用服务器 tick 编号，避免世界时间在 Pre / AI / Post 之间推进导致同一 tick 重置额度。
- 按控制者、工作组、工人轮转；每轮额外移动起点，使扫描等稀缺额度在全部工人均可调度时仍能轮换。操作上限沿用设计表；单个不可中断回调仍可能超额。
- 站位、位置指令、实际导航统一进入可恢复寻路队列。每服务器最多 8 次、每维度最多 4 次建路，每请求每 tick 一个候选，最多检查 256 个队列项。候选失败后继续尝试剩余候选；预算等待不会计为不可达或触发自适应远程回退。已找到的路径单次转交原工人复用，失败按 10 / 20 / 40 / 80 tick 退避。
- 采矿目标按高度分桶，维护所有者、作业面占用和进度计数；扫描与领取有界，处理大量外部清除不再逐目标扫描全表。方块变化通知通过区块索引定位工作组，新增脏项会使完成验证失效。
- 农业、旧采集接口和容器查找分批扫描。暂停、抢占及关闭释放当前目标；暂停继续保留 AI 接管。恢复前先装配暂停状态、身份及货物，再发布任务。
- 动物和掉落物使用事件维护的分区索引、工作组共享候选及领取；工人保留有效目标。喂养先选动物，再检查食物，避免槽位循环重复查询区域动物。
- 取材和投递按槽位续查；满箱、缺货错峰重试。货物合并堆叠，保留种子预留、18 堆触发投递及原有工具 / 权限语义。玩家返还也分批处理，只插入普通背包槽，满背包后的余量作为独立物品栈掉落。
- 订单格式版本 2，保存稳定 `orderId`、`revision`、暂停、待返还、错误和货物快照；读取旧格式时确定性迁移组身份。后来加载的同组工人加入已有计划。恢复逐条推进游标，每 tick 最多恢复 / 返还 8 项，避免前排大量货物饿死后续订单。
- 离线取消保留待返还记录；新任务与旧任务的待返还记录使用不同键。运行异常将持久任务暂停并保留货物，首次记录堆栈，后续不自动反复执行有歧义的操作。
- 工作面板查询按控制者和选中工人索引读取，新增扫描、寻路排队、待返还和错误状态翻译。过滤 ID / 标签键按不可变配置缓存编译，标签内容仍查询当前注册表。

## 保存与异常退出证据

- 真实 `SavedDataStorage` 写盘、关闭再打开，保留待返还状态、暂停、9 个钻石以及稳定订单身份。
- 离线取消的货物快照不受外部可变 `ItemStack` 修改影响，编码往返仍保留 7 个钻石。
- 两名工人分两次恢复后只有一个共享计划；农业暂停后释放目标，另一工人可继续收获。
- 在隔离客户端执行显式世界保存，再结束本任务的测试 Java 进程；重新打开副本时读回 64 份订单和 4 个稳定组身份。这里只证明此前保存点的订单可读回，未证明强杀瞬间所有背包、箱子、方块和货物跨文件一致。
- 订单快照只有实际内容变化才标记脏；保存记录时和读取货物时继续进行防御性复制并剔除空栈。

**保存边界：** `setDirty()` 是待保存状态，不能保证每个工作动作立刻落盘。玩家能力主数据仍由独立系统保存。本轮没有实现跨订单、玩家背包、工人装备、容器和方块的原子事务；第三方容器回调部分执行后抛错时也不能安全盲目重放。各取材 / 收获 / 投递 / 返还节点的强杀故障注入及玩家能力专项恢复仍待验证。

## 客户端测量口径

测试驱动：`MentalWorkClientSmoke`；入口：`tools/vfxgraph-editor/scripts/mental-work-client.init.gradle`。

```powershell
.\gradlew.bat runClientDev -DisDev=true -I tools/vfxgraph-editor/scripts/mental-work-client.init.gradle
```

默认运行 6400 tick，预热 400 tick，采样 6000 tick。4 组各 16 名工人，每组 512 格泥土，周期补充目标并清空输出箱，另生成 4160 个分散放置、无 AI 的背景牛。定期断言 64 名工人、4160 个背景实体均存活，64 任务和 4 组一直存在；每组都必须有产出。测试对象为单控制者采矿，不能替代混合工作和多人实服档位。

统计工作预算已测量作用域（调度、建路、工作实体索引维护、工作区域方块变化）耗时、操作计数、每组交付量，以及服务器 Pre 到 Post 事件区间耗时。后者包含其他服务器逻辑，但不等价于原版完整 MSPT；详细状态编码和所有控制保持回调尚未单独纳入工作计时。补充测试方块、清空箱子的驱动耗时另外记录，不计入生产工作样本。

开发过程中的无效采样不用于验收：最初测试工人受环境伤害减少；后续发现预算使用世界时间重置；另一轮背景实体过度堆叠引入大量碰撞。均保留日志并修正测试条件。最终以 `build/mental-work-client-validation-v2/report.txt` 的结果为准。

## 仍需完成的设计项与验收

- 同硬件同世界的优化前基线和 1 / 16 工人吞吐对比尚缺，不能宣称性能提升百分比。
- 128 工人 / 32 组实际世界压力、8 / 32 位真实客户端、跨维度并发、混合工作模式以及与流场感知 / 真空领域叠加的总成本尚未实测；纯队列测试不能替代这些实测。
- 首次目标发现、首次建路服务、就绪排队的分位数未完整采集。当前每组每 tick 最多 64 次分类，4096 格单组首次核对至少 64 tick，尚不满足设计的单组 20 tick 调优目标；后续应在保持切片大小及公平性的前提下调度多轮切片。
- 当前恢复是有界轮询；事件优先恢复队列、基于地形版本和体型的负结果缓存、交互寻路独立预留份额未实现。现有短期重试会自行恢复，但不等同于这些增强。
- 状态查询已索引化，配置 / 状态的版本增量网络协议、详细订阅和重同步仍沿用后续阶段计划。没有改变客户端现有协议。
- 当前同步执行通过所有者校验和关闭旧请求避免过期操作，尚未引入面向异步外部执行器的公开领取代次对象，也未新增非玩家执行上下文。

这些项目不能标记为已完成。本轮交付的是可独立运行、已覆盖正确性回归的核心优化，完整设计的性能验收仍需继续。
