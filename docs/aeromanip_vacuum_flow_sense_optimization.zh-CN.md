# 真空领域、流场感知优化方案

日期：2026-09-29。本文对应用户所称“气流感知”，仓库中的技能名为**流场感知**（`flow_sense`）。下文保留优化前分析与批准的设计；现已实现范围查询会话、批量观测、实例化标记与持续领域特效。实测结果和未覆盖项见 [实施与验证记录](aeromanip_vacuum_flow_sense_validation.zh-CN.md)。

## 1. 源码结论与风险边界

以下为源码分析和按 20 TPS 推算的工作量，不是性能剖析结果，不能据此断言这两个技能已经导致过看门狗崩溃。

| 路径 | 当前行为 | 风险 |
| --- | --- | --- |
| `VacuumDomain.Events.onPlayerTick → applyDomain` | 每位施术者每 2 tick 查询一次半径 50／100 格球形范围；范围倍率允许最高 4 倍 | 最大配置半径达到 400 格；大量区段与实体参与筛选，多名使用者叠加 |
| `AreaEffectTargets.inSphereByBoundsCenter` | Minecraft 区段空间查询后，构造全部合格实体的列表 | 虽有空间索引，但后面的 96 个处理上限不能限制前面的查询、筛选和列表分配 |
| `VacuumDomain.applyDomain` | 每次只取列表前 `maxBonusEntitiesPerTick` 个，默认 96，硬上限 96 | 查询顺序稳定时，后排目标长期得不到处理；不存在跨 tick 的公平游标 |
| `BreathingBubble.Server.protects` | 每个真空目标遍历全部活跃气泡，重复取熟练度、阵营关系、眼部距离 | 真空施术者数 × 受影响目标数 × 气泡数的重复工作 |
| `FlowSense.Events.onPlayerTick` | 半径 24／32 格，倍率最高 4 倍；每 10／5 tick 完整收集目标，再取前 64／96 个 | 全部使用者按世界时间取模，同一 tick 集中查询；超额目标饥饿 |
| `FlowSensePacket` + `AeromanipVfx.marker` | 每目标发送观测包和生成雾环包，各一次；没有稳定标记实例键 | 初始满额 256 包／秒，升级满额 768 包／秒／观察者（未含协议封装）；高频创建临时特效 |
| `aeromanip_mist_ring.json` | 每个雾环三组 burst，配置数 38 + 26 + 22 = 86 | 升级时请求 384 个图实例／秒，名义粒子生成请求量 33,024／秒；实际数量受 VFX 系统的裁剪和容量影响 |
| `FlowSensePacket.Client` | 按实体 ID 保存观测，只在 `snapshot()` 中清除 500 ms 前记录 | 全仓库查不到 `snapshot()` 的调用者；目前可见标记来自雾环包。缓存未接入独立定期过期、断线、切维度清理，实体 ID 复用也有残留风险 |

真空领域的伤害目前为缺氧时每 10 tick 按最大生命值的 5% 计算基础伤害，再走统一伤害管线；气泡保护、队伍关系、水生生物及自身驯养生物的豁免均须保留。流场感知保留隐身探测与潜行玩家的熟练度规则。

## 2. 共用的范围查询与工作预算

建议先抽出公开服务 `org.academy.api.server.ability` 下的范围查询会话与预算接口，具体命名在实现时确定；技能只提供范围、目标资格判断与效果回调。施术者参数采用 `LivingEntity`／UUID 和 `ServerLevel`，玩家熟练度与阵营规则由调用者传入，为精密操作及非玩家施术保留接口。

### 查询方式

1. 按维度管理会话；以 Minecraft 已加载实体区段为基础，按离施术者的距离优先推进区段游标。查询只读已加载实体区段，不加载区块，也不生成地形。
2. 查询本身必须可以在实体迭代中暂停。不能在调用一次无界 `getEntitiesOfClass` 之后才检查时间。如果区段查询 API 无法保存安全游标，再接入实体加入／移出区段通知维护紧凑的 ID 索引；避免在每个技能或每 tick 复制全世界实体。
3. 固定数量和软时间预算同时生效，覆盖区段枚举、候选筛选、效果执行、包组装。第一轮调参起点：每维度每 tick 合计 256 个候选检查、96 次效果回调、1 ms 软预算；这只是待压测的起点，须按实际负载调整。
4. 使用者轮转，目标也轮转；近处优先发现，已经进入队列的远处目标按等待时间获得服务。不得每次重置为列表前 N 个。保留服务端已有的单施术者处理上限，并准确计算所有会话共同消耗的总预算。
5. 主线程分批操作 Minecraft 世界和实体；禁止把活实体、世界查询或伤害事件交给工作线程。软预算不能抢占单次第三方伤害回调，需要另记单次回调最大耗时。
6. 使用稳定实体身份、维度、会话代次和上次服务 tick；死亡、卸载、退出、换维度、关闭技能时清理。执行前再次验证存活、范围、阵营和保护状态。

### 预算不足时的行为

正常负载按原有间隔完成一个覆盖周期。超出容量时延后尚未处理的任务并轮转，暴露队列年龄和完整覆盖耗时。不能同时承诺任意数量目标的固定刷新间隔与固定 tick 预算。

取消已离开范围的任务；不补发历史伤害，不在恢复后一次性扣除积压空气或制造伤害爆发。普通场景保留原节奏，压力场景允许效果／发现延迟，并记录其 P95、最大值。这是明确的过载降级，需在实现验收时核对体验。

## 3. 真空领域

### A. 降低重复计算

- 将中心、半径平方、里程碑、目标上限及伤害来源每轮解析一次。候选缓存复用，以区段变化和移动更新覆盖区域，范围内目标在施加效果前用实时状态复核。
- 呼吸气泡建立按维度、空间小格组织的活跃保护索引。每个目标只查询相邻保护球；眼部位置、熟练度、支持目标规则保持原语义。
- 同一 tick 对同一目标的气泡结果可复用，但必须绑定气泡集合版本、保护者与目标位置，以及影响资格的阵营／熟练度版本。无法可靠失效时只复用气泡几何与邻近候选，最终资格判断实时执行。

### B. 按期执行与公平性

- 每个领域维护目标轮转游标，气息处理正常每 2 tick 到期；伤害单独维护 10 tick 到期时间。不能在任务被分批后继续只检查“施术者 tick 是否整除 10”，否则某些目标会永远错过伤害时刻。
- 多个领域的重复作用与伤害来源保持现有规则；不要为了节流擅自合并来自不同施术者的伤害。
- 关闭、死亡、断线、换维度时显式关闭压缩空气租约并释放查询会话。资源维持与扣费继续按原技能规则执行，不因查询队列拥堵而免费持续生效。

### C. 显示

- 领域视觉改为按施术者 UUID／维度复用一个持续实例，开始、变化、结束和低频心跳同步；客户端跟随施术者插值。可复用已有 VFX 的 `spawnOrRefresh`，但需验证图刷新是否会再次触发 burst。
- 保留当前最大 12 格视觉半径的设定，避免误把 100／400 格逻辑半径直接转为巨型透明特效。范围说明如需增加，单独设计低亮度边界指示，不增加密集粒子。

## 4. 流场感知

### A. 批量、差量观测协议

- 将逐目标的两个包改为一组有长度上限的观测批次：会话代次、维度、服务端 tick、增加／更新／移除目标列表。每次最多 64／96 个目标更新，作为带宽预算；完整可见目标集合按轮转逐批更新，避免把同一个前 N 列表当作永久显示上限。
- 服务端继续决定是否可感知；距离、隐身、潜行规则沿用技能逻辑。只有实际需要显示的数据进入包：实体 ID／身份标记、中心、尺寸、速度或方向。能从客户端已跟踪实体获得的运动不重复高精度传输；客户端未跟踪的合法感知目标保留服务端位置兜底。
- 仅在位置／速度超过阈值、目标资格变化或心跳到期时发送；量化精度从 1/32 格起压测，目标是静止场景明显少包、移动目标不跳动。
- 使用者按 UUID 分散到刷新窗口不同 tick。空结果和关闭状态必须发送清空／删除，不能依赖不断生成特效来表示状态。
- 批次不得把“未出现在当前批次”解释成删除；只有明确移除、完整快照提交或租约过期才移除。TTL 根据完整轮转周期设计并设置上限；队列过大时先降低远处更新频率并告知覆盖延迟，防止普通轮转就让标记反复过期闪烁。

### B. 稳定、轻量的显示

- 每个目标只维护一份稳定标记，客户端每 tick 插值更新；停止为同一目标反复创建 86 粒子的雾环。
- 初版采用批量绘制的简洁轮廓／方向提示，颜色和透明度稳定，渐入渐出，无高亮叠加闪烁。近处与视野内目标优先更新；远处简化几何。具体图形先做游戏截图对照，不将矿物的方块轮廓直接套到实体。
- 显示数据由服务端授权，客户端不能自行遍历所有实体补齐被规则隐藏的目标。实体暂未跟踪时使用观测点标记，避免显示成凭空消失。
- 活跃实体标记数有独立内存上限与分批刷新策略，不能通过“减少到几个标记”解决卡顿；超额淘汰按过期、离开范围、等待时间确定，并纳入密集场景覆盖率验收。

### C. 缓存生命周期

- 删除未消费的旧观测路径或使其成为唯一显示数据源，避免观测包与雾环包双轨并存。
- 独立客户端 tick 执行定量过期清理，不在每帧 `snapshot()` 中全量复制 Map。采用逻辑 tick 与会话代次，避免墙钟变化和实体 ID 复用造成残影。
- 技能关闭、断线、世界卸载、切维度、资源重载都清除标记与待处理批次；旧会话包到达时直接拒绝。

## 5. 实施顺序与验收

1. **基线测量**：分别给范围查询、资格筛选、气泡检查、效果回调、编码发送、客户端更新／绘制加采样计数。只周期汇总，不逐目标打日志。记录 P50／P95／P99／最大值、查询候选数、包数／字节、图实例与粒子请求量。
2. **优先修复流场感知**：观测缓存生命周期、批量协议、稳定标记；随后错峰与公平查询。服务器和客户端协议一并升级，明确不兼容旧包格式。
3. **真空领域**：先保护查询去重与缓存失效，再接入共用预算服务和目标到期调度；最后改视觉实例复用。
4. **回归矩阵**：每技能 1／8／32 名施术者，范围内 32／96／512／4224 个实体，默认和最高范围倍率；覆盖密集单区段、稀疏跨区段、不同维度、气泡 0／8／32 个、多个领域交叠。记录测试硬件与基线，不能只凭“没有崩溃”通过。
5. **机制回归**：真空空气扣除、每 10 tick 伤害、队友／宠物／水生豁免、气泡启停移动与资源耗尽；流场的隐身、潜行各里程碑、移动插值、卸载、重连、ID 复用、关闭立即清空；超 96 个目标不得固定遗漏同一批。
6. **初始性能目标（待测）**：普通场景两项技能合计服务器 P95 < 1 ms／tick；压力下遵守候选与效果硬数量预算，软时间超支归因到具体单次查询／回调。流场客户端新增 CPU／GPU 各 P95 < 1 ms（1080p 基准机），静止满额观测包数降低至少 90%，稳态图实例数不随运行时长增长。
7. **延迟验收**：96 个以内目标保持原技能刷新节奏；超额场景报告每个目标完整覆盖周期与最久等待，持续静止 4224 实体时不得出现永久饥饿。若延迟无法接受，调节预算或降低远处刷新频率，不能隐瞒效果降级。

性能目标需实测校准，特别是第三方伤害事件无法由本模组的协作式预算抢占。完成每阶段后按仓库要求运行测试、开发／发布构建和真实游戏压测，再决定下一阶段参数。

## 6. 实现时确定的细节

- 公开 API 为 `AreaQueryService.open(...).update(...)`；施术者接受 `LivingEntity`，技能通过 `Effect` 提供资格、效果及清理回调。采用实体生命周期事件维护的 `SectionEntityIndex`，分别保存实体原点与碰撞箱中心，保留两项技能原来的距离语义。游标按近到远的区段壳层推进，单次探测可暂停。
- 每维度每 tick 上限为 256 次候选检查、96 次效果回调、4096 次区段／实体探测，软预算为 1 ms；单会话最多跟踪 8192 个目标。索引维护独立计时，不能把查询计时当作全部新增开销。
- 实际错峰采用全局会话轮转与独立目标到期时间，无世界时间取模集中刷新。超载时推迟服务，每次只执行一次到期效果，不补发历史伤害。8192 目标以上按队列顺序轮替；不能保证任意规模、任意并发下固定刷新周期。
- 流场每批最多 96 条更新、96 条显式移除，位置量化至 1/32 格；静止目标每 20 tick 心跳。客户端租约根据已知目标数量与最长排队延迟调整至 60～600 tick；内存上限为 8192 个标记。旧包注册名改为 `flow_sense_sync_v2`，服务器与客户端须同步升级。
- 流场采用一次实例化绘制的浅青色空心菱形，不创建雾环或泛光粒子。重载释放显示资源后，允许同会话的服务端心跳恢复；服务端显式关闭仍永久封闭该会话代次。
- 真空领域每个目标分别维护 10 tick 伤害期限。气泡只查询附近保护者并实时复核资格，不缓存可能失效的队伍判断。领域每名施术者保留一个持续粒子实例，20 tick 心跳，半径仍最多 12 格；专用图的名义生成率为 26 粒子／秒。
