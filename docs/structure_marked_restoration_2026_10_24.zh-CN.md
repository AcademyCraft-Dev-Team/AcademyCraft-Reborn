# 技能物理结构标记与静止归块

同日后续修复：树冠/台阶支撑、有限向上让位，以及本地管理员批量归块见[补充说明](structure_restore_all_2026_10_24.zh-CN.md)。下文的自动归块范围保持不变；保护事件的新管理员分支可能没有创建元数据，应改用 `provenance()` 判定。

本轮实现服务端自动回收 ACR 技能生成的物理结构，同时支持本地 SubLevel 与已验证版本的 Sable。所有者离线后仍执行相同策略。没有 ACR 技能创建标记的旧结构、管理员创建的结构、航空学等其他模组创建的 Sable 结构均不进入自动归块。仅被 ACR 技能选中、推动、旋转或投掷的既有结构不会补上标记。

## 接入范围

矢量动能投掷、电磁磁化控制、空气高速喷射的默认创建入口，以及对应精密操作提取节点，都通过 `StructureCaptureRequest.withSkillCreation` 写入同一份创建元数据。控制、旋转、回正、旋转保持和发射节点沿用结构的创建标记，不重新分配归属。显式租约、提取动作、角控制、实际挖掘或容器交互期间推迟归块。

标记包含原创建事务、根结构身份、所有者 UUID、技能 ID、创建时间和版本化归块策略。捕获事务先保存源/目标及标记，随后才发布成功；读档恢复也遵守此顺序。`StructureUpgradeBootstrap.LIVE` 的 provenance 和 restoration 现为实际服务；DRAFT 占位接口继续禁用。第三方通过公开捕获 API 指定技能归属时，应提供真实主体，不能把该参数当作玩家网络输入直接信任。

## 服务端设置

配置位于 `config/academy-server.json` 的 `generic.structureRestoration`：

```json
{
  "enabled": true,
  "allowOfflineOwners": true,
  "restTicks": 100,
  "checkIntervalTicks": 20,
  "candidatesPerTick": 4,
  "retryTicks": 100
}
```

默认每个候选约 20 tick 采样一次，持续静止至少 100 tick 后尝试归块；服务器有较多候选时会因预算延后。静止同时要求线速度、角速度、累计位置和角度漂移足够低，地形可解算且确有地面支撑。地形缺失时的暂停、卡在侧墙上或技能保持悬浮不会被直接当作落地。

每 tick 最多检查 4 个到期候选、最多尝试一笔回填。Sable 使用独立的轻量运动观察，不因候选轮询构建碰撞几何；其几何缓存改为逐项 LRU 淘汰，避免超过 256 活体后整表清空。平时不遍历结构全部方块，不为检查增加区块加载票据；完整内容与目标验证只在静止资格满足后执行。目标冲突时保留原结构并延后重试。关闭 `enabled` 只停止新候选，已经作出持久提交决定的事务仍会完成清理。

## 回填与持久化

按当前所在地回正为竖直、最近的 90° 整数倍朝向，不回传到最初挖取地点。保持完整方块状态，并对旋转后的方块状态执行相应转换。整批目标必须在已加载区块中、全部为空气、满足世界边界和方块生存条件，且无实体、其他物理结构或遗留结构占位。验证失败时不覆盖原世界方块，也不删除源结构。

当前支持普通方块与可在完整回填镜像中生存的非实体方块。不自动处理含方块实体、流体、内部实体或其他未知内容的结构；Sable 原生关节仍有效时也会延后归块，不擅自解除连接。单体非空气内容最多 256 格，包围格网扫描最多 32,768 格。超出范围时保留结构，不能将本实现理解为无条件容量回收或区块卸载归块。

事务顺序为：保存源内容 → 持久化准备记录并隔离源 → 写入并强制保存目标 → 持久化 COMMIT 决定 → 清理并保存源 → 释放后端容量 → 删除创建标记 → 发布完成。准备阶段中断后，只有完整目标镜像仍匹配时才回滚为唯一源；COMMIT 后中断继续清源，不再重写可能已被玩家编辑的目标。待恢复源在启动时禁止参与解算、碰撞、选择和客户端发布。日志或来源证据异常时保留隔离状态供核查，不猜测所有权。

以下异常会保留事务与容量：提交前目标被挖掉或改动、部分写入或部分回滚、Sable holding 缓存身份冲突、存储槽被外部结构复用，以及源槽已清空但占用位归属无法证明。尤其是“清源完成、占用位尚未持久释放”的中断窗口，不能承诺自动回收。不得直接删除日志或补造方块绕过这些校验；这类存档需要核对源、目标与后端存储后处理。

持久记录在世界的 `data/academy/structure_provenance` 和 `data/academy/marked_restoration`。更新服务端或备份世界时应把这些目录、宿主区块、物理后端存储视作同一份存档整体。

本地共享 plot 维度沿用暂停常规 tick 的优化；已有租用地块的实体读取通过预算队列异步准备，再消费已完成结果，归块预演不等待磁盘、不将未知实体内容当作空。本地已标记结构挖空后在内容与实体确认为空时释放地块。Sable 的归块清理同时强制保存 holding 索引、数据槽和 occupancy 位图，未完成事务的 plot 在分配前保持占用。

Sable 自身拆分产生的子结构目前不会继承 `SKILL_FRAGMENT` 标记；Sable 普通永久销毁可能留下来源账本记录。本轮不会为解决这些边界而给外部模组结构自动补标记。自动归块完成的结构会正常退役标记；拆分继承和普通销毁后的持久标记回收仍需要独立实现与验收。

## 保护事件与离线归属

所有回填在写世界前发出可取消的 `StructureRestorationEvent`，提供宿主、结构身份、创建元数据、完整目标列表和 `offlineOwner`。取消后原结构与标记保持，之后重试。在线所有者还经过宿主 `mayInteract` 与 `BlockEvent.EntityMultiPlaceEvent`；离线时不创建假玩家，也不伪造在线权限。

服务端已按用户要求默认允许离线归块。依赖在线玩家的领地插件应监听 `StructureRestorationEvent`，使用 `metadata().ownerId()` 与每个目标坐标判定；需要阻止时调用 `setCanceled(true)`。归块属于内容搬运，不产生方块掉落，不重复调用破坏掉落逻辑。
