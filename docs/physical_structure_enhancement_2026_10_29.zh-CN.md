# 物理结构效果、传送与多人同步更新

本批基线 `741e9b54 新增精密结构群组平移与有限力预算`，承接用户提出的传送使、结构断裂、多人表现、动能投掷和精密操作五项更新。用户随后明确：**64 格无碰撞到期不爆炸**；精密操作在保留原功能的同时，应让最简图足够短；本轮完成同维度传送，跨维结构迁移留待后续。实现与本批必要验证已完成，总报告见 [`physical_structure_enhancement_validation_2026_10_29.json`](../validation/native_structure/physical_structure_enhancement_validation_2026_10_29.json)。

## 传送与方向

公共 `StructureTeleports` 负责整结构姿态传送，前后保持内容与运行实例，不将投影实体当作一格方块移动。目标需完整加载并通过世界边界、地形/实体/其他结构碰撞、控制占用与技能权限检查；拒绝时保留原位置。旋转以质心为中心，线速度与角速度按姿态变化旋转。

快速坐标传送、区域传送、防御传送和传送精密动作共用服务。快速坐标默认保留朝向，潜行时按玩家视线对齐；区域动作按区域旋转，部分选中或镜像不能只传结构一部分。区块跃迁地图及区块交换的边界与复跑以传送专项记录为准。同维传送是当前实际实现范围，跨维度没有内容所有权迁移事务，明确拒绝。

原生瞬移单独递增 `teleportRevision`，服务端不沿跨越路径承载乘客；客户端收到瞬移标志后同时重置渲染、接触和未消费承载帧，避免把瞬移显示或碰撞为穿过中间地形的快速平移。

站在结构上的宿主玩家或生物不会自动随结构瞬移；空间协同仍按其自己的队友/友方和本人来源规则分别选择目标。客户端与服务端须使用本批同版 JAR，本次新增网络字段不作为新旧版本混用的兼容协议。

## 原生连通断裂

原生结构的内容编辑完成后进入合并队列；每个宿主每 tick 最多处理一个拓扑转移，不在每次物理步扫描所有结构。六面相邻的方块组成刚体，连接被破坏后，各不相连分量成为独立结构。纯算法上限 4096 格、64 片，确定排序且完整覆盖；超过预算时保留现有所有权，不返回部分拆分。

`SubLevelFractures` 采用独立的原子写盘事务目录 `data/academy/sublevel_fractures`。先保存当前源 plot 与完整方块/箱子镜像，再分配隐藏子 plot，验证全部目标后写入提交决定，最后清理并退休父体、发布子体。各子体继承来源和父体的线/角运动，质心速度包含刚体角运动的贡献。子体内容以状态/完整载荷调色板及坐标数组压缩在单条 opaque envelope 内，不放宽普通捕获日志 256 格的准入限制。低异质的 4096 格可保存完整所有权，高异质大 NBT 仍按既有 1 MiB 预算拒绝。

提交前失败保留父体并删除经过验证的副本；提交后失败继续完成所有权转移。未知、损坏或不可读日志不会当作“没有事务”，相关结构保持隔离；观察结果按服务器缓存 20 tick，事务写入/删除后立即失效。恢复按日志方向执行，不重放掉落。当前支持的箱子/木桶镜像、完整双箱组、无开放容器及无游离 plot 实体等条件仍须满足；缺乏刚体碰撞形状的分量、不支持的内容或超过日志 1 MiB 镜像预算时保留原所有权。4096 格为拓扑扫描上限，不代表任何 4096 格复杂箱体都可在镜像预算内完成拆分。

Sable 继续使用其原生连通拆分，Academy 的来源继承与伤害重发现路径负责后续子体。通用冲量驱动的 S4 多片碎裂规划 API 仍与本批“断开连接后拆为独立刚体”区分；未将旧 scaffold 标记为已完成。

喷口跟随其支撑格转移：原生按事务中唯一局部格归属映射子体，Sable 则用拆分前后世界格中心、法向和完整载荷证明新格。只在原挂载和所有者仍匹配时更换支撑引用，不续充激活、不改 temporary。无法证明映射时保持原缺支撑处理，不猜测吸附其他结构。旧能力控制句柄不继承给新子体。

## 动能投掷

标准/增强发射速度为 75/90 格每秒，沿实际姿态对下一步占据区域做精确扫掠；可破坏方块使用公用技能破坏、保护事件和真实掉落路径移除，排除发射源及其相关碎片。空心或旋转结构以真实局部盒加 0.02 格武器接触包络预破障，覆盖求解器接触边缘；求解器和实体碰撞盒本身不变，不能用大包围球直接铲除孔洞内的方块。最多 16 个受理飞行同时逐 tick 推进，全服最多 64 条含终结结算的记录，每玩家最多 4 条；不会让已经受理的飞行随机跳过预破障帧。单体几何最多 128 盒、质心包围半径最多 31 格，超限在实际赋速前拒绝并保留原控制。

穿障效果按实际质心累计路程最多 64 格。**无碰撞到期仅撤销增强，不产生爆炸、不拆解结构，也不把它还原为方块或掉落；普通物理运动继续。** 有效实体命中、实际扫掠接触，或障碍仍新鲜且物理步受阻/失去接近速度的保守后验证据，才可触发终结。后者还排除新租约、内容/实例变化、瞬移及其他动态体干扰，不把单纯预测相交当作撞击。保护、缺加载范围、预算拒绝等不是授权碰撞，不因此爆炸。

终结使用有限范围破坏与爆炸反馈，源结构及经确认的碎片按真实方块破坏回调产生掉落。不能复制箱子物品；未授权格或输出结果不确定的格仍保留。本批增强依赖在线玩家授权，重启或玩家离线后不续跑破坏效果，普通结构内容保留；不会借用一次性持久发射票据反复授权每 tick 的路径破坏。

瞬移事件撤销匹配飞行，保持传送后的速度；即时预破障还用可选 `SourceWitness` 在扫描、回调和变更前复核源实例、版本和姿态，阻止同步破坏回调中瞬移后继续清扫旧路线。本批没有改变已经触发的分批爆炸的全局重入取消契约，也不承诺回滚已经受理的爆破效果。

## 多人同步

原生姿态按观察者合并为 `SubLevelPoseBatchPacket`，每包最多 256 体，保持双精度与原有每物理 tick 更新频率。客户端每批只排入一次处理，避免为每个结构分别提交主线程任务；未收到完整内容的姿态增量仍忽略。静止体保持静默，内容未变时不重发方块和碰撞形状；没有观察者时不为同步构造几何。

同步兴趣以实际结构世界包围范围到玩家的距离计算，进入半径 256 格、退出 272 格，避免大型结构边缘靠近玩家时因原点太远而消失，也减少边界反复重发完整状态。该优化不改物理求解频率或将碰撞降为外框。

256 体的编码测试证明批包比逐体姿态包减少至少 15% payload，消息数量和客户端任务数按批缩减。最终[真实多人专项](multiplayer_structure_batch_2026_10_29.zh-CN.md)使用专用服务器及两个独立 TCP 客户端、八个动态刚体：两端各 99 批 / 792 条姿态，旧逐体包 0，姿态消息数减少 87.5%；服务端 199 个移动 tick 间隔 P50/P95 为 50.0136/52.0096 ms。这不是整体流量字节、MSPT 或 FPS 比较。

远离、返回、删除与断线清理均通过。尤其在重新创建八个活动投影后断开连接，两端实际丢弃各八个投影、清空旧 level 的快照/ID/承载帧并注销碰撞索引；测试保留旧 level 的强引用，不能靠 GC 假通过。清理在生产 tick 入口执行，修复原 WeakHashMap 值中实体反持有 level 的生命周期问题。

## 精密操作

详见[精密操作专项](physical_structure_precision_2026_10_29.zh-CN.md)。基础动作仅需“施放触发 → 动作”两个节点；未接目标输入时选取准星整结构，移动默认沿视线引导 3 格、持续 1 秒，结束自动释放。单结构输入可直接连接，多个目标才使用集合。高级控制句柄、锚点、筛选、显式方向/姿态/时长均保留，旧图 ID 和配置兼容。

单体移动改为等待施力窗口后再继续流程，避免“移动 → 释放”在同一 tick 抵消移动；结束回传原控制，群组动作回传原集合。程序取消会清理其自身签发的确切控制，不能停止继任者。中英文说明先讲输入、作用和结果，再说明能力条件和边界。既有精密编辑器久置漏绘尚未定位，未用推测性渲染改动掩盖。
