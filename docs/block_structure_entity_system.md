# 方块结构实体化系统

## 目标与边界

本系统为能力技能、精密操作程序和其他服务端逻辑提供统一的方块结构操作 API。首版覆盖：

- 从明确位置集合或六向连通区域捕获方块；
- 保存方块状态与方块实体 NBT，并将原方块原子化移出世界；
- 将结构作为单一实体生成、移动、施加冲量、投掷和启停重力；
- 使用随水平旋转更新的整体 AABB 与世界、实体发生碰撞；
- 让站在结构顶面的实体随平台的实际位移移动；
- 将水平朝向吸附到最近的 90 度，并在当前位置对齐方块网格后还原；
- 在捕获、生成或还原中途失败时回滚世界数据。

Sable 使用独立动态坐标空间中的“子世界”，实际方块位于隐藏 plotgrid，能够继续运行区块、实体和方块实体。这里借鉴其“独立姿态、服务端物理、客户端插值、装配生命周期”的分层，但不引入子世界、隐藏区块或大范围 mixin。当前需求以能力短时操纵为主，结构快照实体的边界更小，也更容易控制兼容性和网络开销。

## 模块

公开 API 位于 `org.academy.api.common.structure`：

- `BlockStructureApi`：捕获入口；
- `BlockStructureCaptureOptions`：数量、NBT 大小、重力、静止还原与捕获策略；
- `BlockStructure`：技能与非玩家实体共用的稳定操纵接口；
- `BlockStructureSnapshot`：不可变、原点相对的结构数据；
- `BlockStructureGridAlignment`：纯坐标网格吸附算法；
- `BlockStructurePlacementPolicy`：还原覆盖策略；
- 捕获与还原结果类型：返回稳定状态和问题方块位置，不依赖异常表达正常失败。

内部实现位于 `org.academy.internal.common.structure` 和
`org.academy.internal.common.world.entity.structure`。客户端渲染器逐块提交原版移动方块模型。

## 生命周期和不变量

1. 调用方在服务端选定位置，并提供纯函数式捕获策略。
2. 系统去重、排序并验证所有位置、区块、方块和方块实体数据上限。
3. 所有数据成功快照后，系统无掉落地移除方块并生成结构实体。
4. 能力逻辑仅通过 `BlockStructure` 设置速度、冲量、重力和水平姿态。
5. 还原前先计算完整目标集合，并验证区块与占位；只有全部合法才开始放置。
6. 成功还原后才移除结构实体；失败时实体及其快照继续存在。

关键不变量：

- 服务端是世界数据和物理状态的唯一权威；
- 单个快照最多 4096 方块，默认捕获上限为 256；
- 快照坐标相对其最小角，且不能重复；
- 默认不能捕获不可破坏方块，调用方可通过策略进一步收紧；
- 默认还原只允许写入空气，显式传入策略才可覆盖可替换方块；
- NBT、速度和数量都有硬上限，网络解码再次验证数量；
- 当前只支持绕 Y 轴旋转，还原时使用原版 `BlockState.rotate` 同步方向属性。

## 调用示例

```java
var result = BlockStructureApi.captureConnected(
        serverLevel,
        selectedBlock,
        BlockStructureCaptureOptions.defaults()
                .withRestoreWhenSettled(true)
);
result.structure().ifPresent(structure -> {
    structure.setVelocity(lookDirection.scale(1.4).add(0.0, 0.35, 0.0));
    structure.setGravityEnabled(true);
});
```

已有快照也可以通过 `BlockStructureApi.spawn` 直接生成结构实体，不会读取或移除当前位置的世界方块，适合能力技能生成预定义结构。

精密操作节点应组合这一公共入口，而不是重新实现方块移除、NBT 保存或还原流程。非玩家实体也可直接持有 `BlockStructure`，冲量按当前“每方块一质量单位”的质量模型换算速度。

## 当前交互模型

结构的旋转后水平外包框与完整高度组成整体 AABB。它能阻挡其他实体和自身世界运动，并在每次实际位移后搬运原先站在顶面容差范围内的实体。该模型适合规则、小型、短时移动结构，但有两项明确限制：

- 凹结构的空洞和不规则边缘仍被视为实心；
- 结构旋转本身不会对周围实体产生扫掠推力，仅平移会搬运顶面实体。
- 方块实体 NBT 会完整保存，但实体化期间不 tick、不开菜单，也暂不提交方块实体专用渲染；
- 独立流体方块和依赖方块实体专用渲染的模型可能在实体化期间不可见。

## 后续阶段

1. 将各方块碰撞形状在局部空间合并为分区体素碰撞，取代整体 AABB。
2. 为结构旋转增加扫掠碰撞和角速度，同时定义全方向方块状态旋转适配器。
3. 为需要运行的方块实体提供受控 ticker、交互代理和菜单定位；默认仍保持冻结。
4. 将结构快照按分区增量同步并缓存网格，降低大结构的生成包和逐帧提交成本。
5. 增加结构断裂、质量/质心/惯性与伤害模型；物理后端保持接口化，可选接入 Java 或原生刚体引擎。
6. 接入能力技能和精密操作节点时，只新增选择、消耗、权限与反馈层，不复制基础结构逻辑。

## 验证清单

- 单元测试：角度吸附、四向坐标旋转、矩形结构整体网格平移；
- 构建：开发与发布变体；
- 游戏内：含方块实体结构的捕获/重载/还原，水平与垂直碰撞，玩家站立搬运，落地自动还原，目标被占时保持实体；
- 兼容：活塞、流体、跨区块边界、受保护区域和卸载边界由调用策略与集成测试逐项确认。
