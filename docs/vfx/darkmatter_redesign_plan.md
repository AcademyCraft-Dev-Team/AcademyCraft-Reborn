# 未元物质特效重做方案

状态：已实施；后续追加了可见性、减小锯齿、独立命中反馈、解构烟雾以及追猎／六翼羽刃更新。实现与验证记录见 [验收记录](darkmatter_redesign/README.md)。以下保留原始设计依据，最终参数与行为以验收记录为准。

## 设计依据

参考视频：[【魔禁】一方通行 VS 未元物质](https://www.bilibili.com/video/BV1q7411Y77o/)。

已查看的关键画面：约 0:18 的破损墙体旁白色物质边缘、0:25 的羽状宽片与破碎轮廓、1:13 的白色羽翼及法则说明。宽片、羽状分叉、白色主体与松散边缘是可采用的形态依据。视频中的高亮大面积铺屏不适合直接搬进可操作的游戏视角。

浏览器在约 1:16 弹出登录窗口，后续光线变化镜头暂未核对。下面“未元干涉改变环境光”的机制以用户明确说明为准；修复和解构是沿用已观察材质语言的游戏设计，不将它们描述成视频中已经验证的技能镜头。

## 总体方向

- 共同材质：乳白、珍珠灰、半透明边缘，局部柔和高光；保留内部明暗，避免白色过曝。
- 共同形态：柔软的不规则薄片、短小羽片、分叉生长前沿、微小物质碎屑。
- 三种不同运动：干涉是环境受光发生变化；修复是物质在表面长合；解构是表面侵蚀并剥离。
- 废弃三个图当前的 `organic_strands` 丝束主体。没有螺旋绕圈、绕身光线或沿视线延伸的白色光柱。
- 保留伤害、范围、资源、熟练度和修复结算。羽毛追加命中后的短暂直线穿出外观，仍按原有规则结算单次伤害。环境光只影响视觉，不额外引入夜间失效或伤害变化。
- 六翼的完整形态仍由六翼技能承担；普通干涉、修复和解构只使用同一物质的局部形态。

## 1. 未元干涉：环境光的异常转化

### 玩家看到的过程

1. 启动时，在作用区域的侧缘或上缘短暂显露少量薄而透光的羽片，作为改变光线的媒介。羽片不从手掌或眼睛喷射，也不排列成通向目标的路径。
2. 持续期间，媒介只保留偶发的边缘反光。前方实体或地形表面的受光斑驳发生轻微变化：不规则的羽片状高光局部亮起、缓慢错动后消退。
3. 实际命中时，在目标表面出现短促的白色接触斑、少量细碎白屑。视觉因果是“原本照着目标的光发生了异常”，不出现施术者到目标的连线或飞行弹道。
4. 停止时，光照变化恢复正常，媒介薄片溶散，目标接触反馈快速结束。

### 光照表达

- 日间由天光方向组织媒介反光和目标接触斑的朝向，表现日照穿过异常物质后的变化。
- 室内或夜间依据局部环境亮度降低外观亮度，保留弱的材质边缘和命中反馈，不凭空生成强烈自发光白柱。
- 光照方向采用客户端近似，不做光线追踪，不改变 Minecraft 实际光照传播或技能伤害逻辑。
- 第一版以表面斑驳和薄片反光完成表达。局部折射是可选增强；只有接入场景颜色采样后才称为折射，不能用白色半透明面片冒充。

### 初始调参范围

- 同一施术者维持一个干涉场；伤害脉冲更新它的强度，不重复堆叠完整图。
- 同时可见的媒介薄片约 4–8 片，普通视角单片不透明度约 0.03–0.08；第一人称近场更低。
- 每个命中目标保留少量表面接触斑，单次约 0.10–0.18 秒。不得整个人物亮白，也不复用解构云。
- 媒介和接触反馈都参与场景深度测试，墙后不会透出整片高光。

## 2. 未元修复：白色物质贴面长合

### 玩家看到的过程

1. 成功治疗或修复后，实际受影响的身体或可见装备表面出现一小片乳白物质。
2. 物质以宽短、不规则的分叉边缘向内长合，形成一层很薄的补片；局部边缘会微微起伏，体现有机感。
3. 补片贴合并收平，随即恢复原有材质，留下极少量消散的微粒。

- 不生成绕身体旋转的丝线，不出现完整白色球罩。
- 治疗与物品修复区分视觉落点，不能只要修了背包里的物品就把玩家全身包起来。
- 第一人称主要展示可见手部、手持物或袖口附近的小范围反馈；头部与相机附近不生成遮挡。
- 背包内不可见物品不伪造漂浮物品模型；若没有可见修复部位，可省略世界中的修复图。
- 仍只在实际结算成功时触发，持续修复合并到同一实例中更新，保留既有节流和 MP 规则。
- 单次建议 0.25–0.40 秒：显露约 0.05 秒，长合约 0.15 秒，其余时间回归原材质。

## 3. 未元解构：贴近目标的侵蚀粒子云

### 玩家看到的过程

1. 目标接触区域浮现疏松的白色微粒与小羽片，形成贴近表面的薄云。
2. 分解前沿沿表面不规则蔓延，局部薄片松散、剥落，转成细小物质颗粒。
3. 颗粒沿表面法线略向外散开，并在短距离内变小消失；没有绕目标旋转的固定轨道。

- 目标轮廓和动作始终能辨认，粒子云保留大量间隙，不用浓雾填满整个包围盒。
- 建议外扩距离约 0.15–0.45 格，单次约 0.35–0.65 秒。
- 活着的实体只做局部表面反馈；真正死亡或方块确实移除后，才允许较明显的散解收尾，避免画面先于游戏状态消失。
- 方块从可见表面出屑；生物随身体或肢体移动。暂不支持精确模型表面的实体采用保守表面代理，不宣称精确贴模。

## 后续参考与羽刃补充

解构补充参考：[Blender 消散几何节点资产](https://www.bilibili.com/video/BV1U8AuzeE87/)。登录后核对约 2:26 的局部拆分画面：较大的表面碎片脱离，边缘细化成小颗粒。本次采用“薄片剥离 → 细屑扩散 → 白雾淡出”的运动关系；不复制视频资产，也不宣称对 Minecraft 模型做真实网格切割。

追猎词条与六翼干涉共用新的白色羽刃图，羽片沿速度方向排列，保留细小锯齿及亮脊。命中后保持原方向穿出并结束，保留原伤害次数；不新增后排伤害。

## 视野保护

“不遮挡”按最终叠加画面验收，不能只检查单个粒子的透明度。

1. 相机附近约 0.6 格内隐藏介质层，在约 0.6–1.5 格间平滑淡入，避免云片穿入眼睛。
2. 第一人称准星附近约 10°–12° 的区域强烈衰减近场媒介；远处目标表面的命中反馈保留，以便确认技能正在生效。
3. 禁用全屏白闪、屏幕雾罩和大片泛光；泛光只用于少量薄片边缘或局部命中点。
4. 通过实例合并、数量限制及稀疏分布控制重叠；多人同时释放时仍须看清地形、目标轮廓与准星。
5. 第三人称保留物质细节，同样不能用实体白墙覆盖场景。

现有渲染器的普通粒子输出有噪声／纹理与深度采样；项目另有场景颜色扭曲通道，但需要显式接入。真实的局部折射不能只靠修改现有三份 JSON 得到。实体、装备贴面也需要合适的渲染锚点／表面提供器，只有跟随实体原点不足以实现。

## 制作顺序与验收

1. 先完成未元干涉：必须一眼看出环境受光变化，且不存在从角色射出的光束；先验收白天、夜间、室内及第一人称追踪目标。
2. 制作未元修复：分别验证治疗、可见装备修复、仅背包物品修复、无实际变化四种状态。
3. 制作未元解构：分别验证方块、普通生物、大型实体、目标死亡／移除。
4. 输出同相机、同环境的开启前后截图及短录屏，检查 F5、近距离、多人叠加、连续脉冲和停止清理。
5. 完成相关生命周期／同步测试、全量测试、开发与发布双构建后，再交付游戏内效果。

通过标准：干涉的来源不是角色枪口；修复表现为长合；解构表现为剥离；三者均无螺旋丝线，目标和地形始终可辨认。
