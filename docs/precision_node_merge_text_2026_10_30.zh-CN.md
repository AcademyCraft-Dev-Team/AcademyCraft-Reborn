## 1. 已有能力与需要改善的部分

当前 `AbilityProgramDefinitions` 实际包含七系：矢量操作、电击使、空力使、传送使、原子崩坏、未元物质、心理掌握。心理掌握并非缺少精密节点：`PrecisionProgramNodeCatalog` 将 `PrecisionGraph.NodeKind` 与 `ON_CAST` 桥接到共享程序体系，另有通用节点与旧图别名。

已有合并必须作为基线保留：

- `ProgramEditorNodeCatalog.commonVisible` 已隐藏旧的四种专用常量，以及整数、大整数、浮点数的专用算术/比较入口；通用数值常量、数值运算、数值比较、类型转换已存在。
- 分类自己的 `caster`、`look_target` 和心理掌握旧 `look_living` 已被通用目标入口取代；旧 ID 仍能用于读图。
- 心理掌握已有十二种旧筛选入口隐藏；`PrecisionProgramAliases` 已迁移五种明确等价的旧节点。
- 三系物理结构群组移动、群组姿态动作已经可只接流程，默认选准星结构；不能把“触发 → 动作”两节点用法当成本提案新实现的能力。
- 单体持有控制与群组窗口控制已经有不同的生命周期。前者输出控制权供连续动作使用；后者批量取得并释放本次控制。界面归并不能改变这些语义。
- `structure/staticize` 当前显示“还原为方块（未开放）”。本提案不将它纳入可用基础模板，也不把“释放控制”解释为还原或删除结构。

需要降低的是选择、连线和读说明的负担：过长标题、同一种操作分散在多个类型/单群组卡片中、默认对象难以发现、状态与错误只像内部日志、动作限制被大段说明埋住。目标不是把所有能力压成一个万能节点。

## 2. 编辑器入口结构

采用“常用 / 进阶 / 兼容”三层，保留按功能与按能力两种浏览方式。搜索始终覆盖当前可用能力；旧图中的隐藏节点正常绘制和检查，但默认新增菜单不列兼容入口。

当前通用可见节点有 155 个，在每系中复用；编辑元数据顺序为 TARGET、COLLECTION、FILTER、LOGIC、FLOW、ACTION、VALUE。新建空图时优先展示本能力动作、触发器和准星目标；从端口拖线时优先展示兼容类型候选。完整分类仍可一键展开，不按简易模式剥夺集合、数值和控制功能。

| 层级 | 内容 | 呈现要求 |
| --- | --- | --- |
| 常用 | 当前能力动作、准星/附近/最近目标、常见条件、等待、结束、基础数值和空间值 | 卡片标题表达行为，默认只显示必要端口；显示未接输入的实际默认行为 |
| 进阶 | 集合运算、明确控制权、局部锚点、精确姿态、来源/材质筛选、共享变量、射线起点、数值类型等 | 可从连线类型定位候选，不要求先学习整个类型系统 |
| 兼容 | 已隐藏旧 ID、不能证明等价的旧心理图语义、旧数值特化入口 | 已有图保留编辑能力；解释替代入口，不强行重写 |

“家族卡片”只代表相同交互范式。选择对象类型、操作模式时，编辑器选用已有真实 ID、配置和类型化 schema；存档仍保存其真实 ID。插件节点没有声明家族时按原卡片显示。不要引入把实体、方块坐标、物理结构都塞入 `ANY` 的运行类型。

模式变更先预览端口差异；旧连接若不兼容则阻止应用并标明冲突，或让用户显式确认替换，整个变更可一次撤销。禁止先删连接再悄悄改变模式。动态 schema 不能只用默认配置验证：数值类型、运算符、集合元素数、传送对象类型、射线/落点瞄准模式都需枚举合法模式。

## 4. 七系专属节点映射

下文 `A/`、`E/`、`F/`、`T/`、`M/`、`D/` 分别表示 `academy:program/{accelerator,electromaster,aeromanip,teleport,meltdowner,darkmatter}/`。旧 ID 不删除。每系分类入口节点由 `BaseAbilityProgramDefinition.entryId` 或心理桥接生成，入口卡片“施放时”不跨分类迁移技能权限。

### 4.1 三系物理结构共用外观、保持各自能力规则

以下结构路径在 A/E/F 三系分别映射，不创建跨能力万能执行器：

| 当前路径 `action/structure/*` | 建议入口 | 默认与进阶端口 |
| --- | --- | --- |
| `extract` | “物理化方块”，能力徽标分别为“动能 / 磁力 / 喷流” | 目标方块默认准星；档位/半径、数量上限、强制磁化、喷口归属等按各系真实配置显示；三个能力的选区、成本、力来源不统一 |
| `control` | 进阶“接管结构” | 必须显式结构；输出“控制权”，供保留控制的单体链；已有被占用结构仍拒绝 |
| `move_group`、`move` | “牵引结构”，模式“自动取得并释放 / 使用已有控制权” | 常用默认前者，保留已有两节点用法；前者接结构/结构集合及位移，后者接控制权、世界落点/局部锚点；不要把两种输入假装同一位移 |
| `rotate_group`、`rotate` | “调整姿态 · 旋转” | 群组/自动模式默认准星或显式集合；持有模式接控制权与绝对目标姿态。UI 必须标明绝对姿态或相对变化，不能只称“角度” |
| `reset_group`、`reset_orientation` | “调整姿态 · 回正” | 保留重力方向回正与各模式的真实旋转预算、完成语义 |
| `spin_group`、`spin` | “调整姿态 · 持续旋转” | 默认轴、角速度、时长在卡片摘要可见；进阶展开“持续持有”模式，不偷偷将长自转截成 200 tick |
| `launch` | “发射结构” | 显式控制链与当前已支持的准星/直接使用路径依原执行器；默认沿视线，发射方向和强度可覆盖；不得给磁力/喷流套用动能投掷 64 格破障规则 |
| `release` | “释放控制” | 释放本次确切控制权，保留结构与惯性；不承诺停止、删除、爆炸、还原、释放其他玩家控制 |
| `staticize` | “安全还原（未开放）” | 留在兼容/实验信息中，原图可识别；不作为可用方案。未来开放时须另做网格、占位和物资事务设计 |

群组仍限制成员数、总力/扭矩、成员来源、整组预检和失败清理；单体仍可使用局部作用点。不会把“八体各自姿态”悄悄改成共同中心公转或刚性队形，也不会把连续控制链改成每次动作重新抢占。

## 5. 保持两节点最简用法

先展示当前已经支持的“施放时 → 牵引结构 / 调整姿态”默认用法，卡片上直接写“对象：准星下整结构”“位移：沿视线 3 格”“持续：1 秒”等真实默认值；高级端口折叠不代表隐藏行为。当前数值按代码导出，后续调平衡只同步默认摘要，不在说明里写死另一份数值。

对尚不支持省略目标的动作，分两种处理：

1. 语义唯一时规划默认目标，例如准星实体、当前事件攻击者。目标在动作启动时固定，等待/重试不重新拾取；未命中按原失败策略结束，不自动寻找附近其他对象。
2. 有多种角色或权限含义时提供明确预设模板，而不是无条件放宽必接端口。例如“使准星生物呆然自失”模板可显示两个用户节点，内部编译展开原准星查询、单实体集合和原动作。展开图可查看，调试与运行预算按真实展开图计；不得因是模板而少算查询、迭代、成本或目标上限。

建议最初的五个模板：

| 用户可见图 | 真实默认语义与边界 |
| --- | --- |
| 施放时 → 牵引结构 | 复用当前自动控制模式，单结构；无准星命中不作用；不改变质量和碰撞 |
| 施放时 → 调整姿态 | 复用当前群组卡片的单目标默认模式；“回正”与“持续旋转”由卡片明确选择 |
| 受击时 → 电弧放电 | 规划模板；目标明确为本次事件攻击者，环境伤害无目标；原友伤/能力/消耗检查仍执行 |
| 施放时 → 使准星生物呆然自失 | 规划模板；对象固定一个合法生物，不偷偷扩展为附近全部实体 |
| 施放时 → 发射采掘束 | 若当前默认方向已可省略则直接复用；否则模板显式展开能力者视线，保持原射程与持续成本 |

目标/落点不唯一的传送、误认对象、隐藏观察者等动作不强求两节点零配置；模板卡片可提供内联目标选择，必须让用户看清“谁、对谁、到哪里”。这比把所有必接输入变成隐式全局查询更容易理解和复现。

默认值优先级统一说明为“已连接端口 → 卡片配置 → 明示预设”。每个动作绑定第一次启动的目标、方向、时长和操作 ID；只有明确的“持续跟随”模式才实时追踪，不能让轮询重算准星、重扣费用或换控制对象。

## 6. 文本、单位和端口设计

节点标题采用“动词 + 对象”，对象查询采用“对象 + 属性 / 选取方式”。能力专有名词保留，内部概念下沉到“技术详情”：`PENDING`、`RETRY`、暂存捕获事务、租约、Vec3、schema 和机器原因码不放进玩家默认说明。

常用说明分四行：作用；未连接输入的默认行为；何时继续下一个节点；关键条件。只有该动作确实涉及的材质、喷口、范围或传送落点限制才显示，不加泛用警告清单。

以下“当前”文本直接来自 `zh_cn.json`，是改写任务样例，不是已经修改翻译：

| 当前名称 / 文本 | 建议名称 / 默认说明 |
| --- | --- |
| “文本转 Vec3” | “解析三维值”——从文本读取坐标、方向或向量；先选择数据类型。未解析成功时不输出目标。 |
| “Vec3 运算” | “三维值运算”——标题旁标“向量 / 方向 / 世界坐标”；检查器只列该类型合法运算。 |

端口展示需要方向语境，不能把全局 `screen.academy.program.port.flow` 直接从“流程”全量改成“完成”：

| 语义 | 建议显示 |
| --- | --- |
| 动作流程输入 / 正常完成输出 | “执行 / 完成”；等待中输出不点亮 |
| 条件分支输出 | “满足 / 不满足” |
| 遍历控制 | “每个成员 / 遍历完成”；索引起点按原 schema 显示 |
| `control` | “控制权”，tooltip 说明仅属本次程序，不是结构本体 |
| `structure`、`structures` | “结构 / 结构集合”，附类型图标；禁止共用“目标”掩盖类型 |
| `position`、`destination`、`block` | “世界位置 / 落点 / 方块坐标”，按节点职责，不用一个“坐标”贯穿所有空间 |
| `motion` / `direction` | “速度向量（格/秒） / 方向（无长度）” |
| `duration`、角度、角速度 | “持续时间（秒） / 目标角度（°） / 角速度（°/秒）”为默认显示；内部弧度/tick 通过明确 UI 换算，精确高级输入保留原单位 |

提议给编辑元数据增加可选的逐节点、输入/输出方向区分的端口标签/单位/默认摘要，未声明者继续使用原 `portTranslationPrefix`。单位换算是呈现层；存档仍是原 float、弧度、tick。不能把实际质量一律写成“kg”，也不能把物理效果持续时间误写成“必定到达”。

当前集合取项描述从 1 开始，文本分段配置从 0 开始。P0 先明确各自起点，P1 可给文本配置增加 `displayOffset=+1` 的“第 1 段”控件，仍写回旧的 `fragment_index=0`；运行端口/输出序号若要换基必须升 schemaVersion 并显式迁移，不能仅改标签让旧图数值变义。

错误默认显示“发生了什么 + 用户能改哪项”，技术详情保留原原因码、节点 ID、操作 ID 和预算。建议样例：未命中→“准星下没有可用结构”；被占用→“该结构正在由其他操作控制”；准备中→“正在等待选区稳定”；地形等待→“正在等待附近地形就绪”；超预算→“选区超过本次数量上限（实际/上限）”；落点冲突→“落点被占用，请调整位置”；未解锁→“需要先解锁：技能名”。保护拒绝不得用“重试即可”误导，也不暴露不存在的玩家/领地信息。

## 7. 兼容、实施顺序和验收

P0 只做呈现和文案：常用/进阶/兼容层、家族索引、真实默认摘要、中文标题/单位、错误可读映射和技术详情。旧 ID、codec、schemaVersion、默认执行参数、能力门槛和费用保持不变。既有“未开放”节点不会因此成为可执行功能。中文/英文完整性和不同模式的端口文本分别验收。

P1 做可审查的快捷模板和内联输入：模板保存标准展开图，记录模板元数据以便再次编辑；不可逆的模板折叠、损失高级端口的修改都应给出预览并可撤销。新默认目标必须有实际运行器支持和启动快照语义，不能只在编辑器里把 required 标成 optional。动作失败的“失败分支/继续执行”若新增，默认仍保持旧图停止策略，并用新 schemaVersion 表达，不伪装成纯文案改动。

P2 才扩展有证据的语义迁移：已有五个心理别名继续复用原迁移；其他等价迁移逐对证明对象域、范围、单位、顺序、空值、事件快照、执行时机、成本和控制清理都相同。原始图保存备份，迁移后再编译，无损时才建议升级；未知插件节点保留且允许原样回写。

验收按以下具体行为：

1. 每个已注册节点都在清单中有“保留、已隐藏兼容、UI 家族模式、规划模板、未开放”之一；每个可见模式均能从真实 codec 解析，端口和保存后的 schema 一致。
2. 当前可用两节点物理用法不增加必接端口；默认对象/位移/持续摘要与运行器一致。所有可选输入都显示明确的未连接行为。
3. 保存并重开一份含高级局部锚点、类型变更、多个触发器、旧心理桥接、共享变量和三系结构控制的图，不丢节点/连线/配置；动态模式变更不静默断线。
4. 源选区准备、地形等待、能力控制重试保持同一操作 ID；目标不漂移，CP 仅首次扣费；结束旧图不撤销继任控制。
5. 实体/结构、世界/局部坐标、方向/速度、当前值/事件快照、生命点数/比例分别做负例，错误连接在编辑时定位到具体端口。
6. 常用查找任务测量首次完成时间、误连次数、打开进阶面板次数和成功率，不只报告菜单数减少。目标为常见任务无教程可完成；全功能用户不必退回手工 JSON 才能表达旧图。
7. 旧图迁移、全部模式、中文/英文文本与真实 UI 绘制须单独回归。长时间编辑器漏绘仍是独立缺陷，家族合并与文案整理不能代替其修复。

本文件只提供设计；速度调整、当前全清单导出及本次构建由主任务单独记录。任何后续节点实现均须遵守仓库 `AGENTS.md` 的验证和提交确认要求。
