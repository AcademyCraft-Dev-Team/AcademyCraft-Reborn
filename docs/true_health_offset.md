# 真实伤害偏移

CTA、VEC 与 DM 法则引爆共用真实伤害结算。普通 DM 伤害类型不变。

## 有效血量

`H = min(R, max(0, M - O))`。R 为旁路读取的实际血量，M 为经过验证的最大血量，
O 为实例状态中 XOR 编码的上限缺口。每次真实伤害先从有效血量计算目标值，
再尝试物理扣血并安装读取投影。物理扣血成功不会再次减去偏移。

目前自动投影仅支持使用 LivingEntity.getHealth 及其原版血池的实体，
包括重写 setter、拒绝负向写入和在子类 tick 尾部恢复血量的实体。
独立血池、完全覆盖 getter 或独立存活判定需要专门兼容；
此类实体保留此前的实际血池写入和短期限血路径，不报告虚假的投影成功。

## 时间及治疗

- 最后一次有效真实伤害后的 200 个游戏 tick 保持偏移。
- 接下来的 200 tick 线性释放，截止时精确清零并移除状态。
- 重复逻辑 tick、重复读取和维护写入不加速衰减、不刷新截止时间。
- NeoForge 治疗事件通过后，按实际接受的治疗量释放对应偏移。
- 普通伤害保留已经提交的损失，不刷新真实伤害计时。
- 未识别的直接向上写入不被当作治疗；停伤后的衰减最终解除约束。
- 如果底层仍然锁在满血，释放偏移会表现为有效血量自然恢复。
  如果底层已实际扣血，衰减不会额外为底层补血。
- 最大血量变化保持原绝对上限，随后仍按原截止时间释放。

## 生命周期和同步

状态绑定实体实例；持久化记录保存原游戏时间，在加载后恢复并重新编码。
死亡玩家的新实例不继承旧约束。图腾和死亡取消释放零血投影；
死亡已提交后冻结为零，不通过衰减复活，也不反复重置 deathTime。

服务器在实体更新后及服务器 tick 结束时维护。客户端仅接收非持久化的
true_health_ceiling 同步附件，不接收服务端掩码，不推算服务端伤害。

## 字节码

MixinPlugin 在应用 MixinTrueHealthOffset 后使用 HealthReadInliner 将读取、
XOR 解码与钳制指令复制进 getHealth，随后移除注入辅助方法。
这是实际字节码内联，不依赖 JIT。数值更新处也直接执行 XOR，不使用共享解码桥。

XOR 和内联仅增加分析成本，不能构成同 JVM 内的安全边界。
持久化包含恢复所需的编码值和掩码；不能宣称存档数据具有密码学保密性。

## 验证

- JUnit：等待/衰减时序、重复 tick、重击、治疗、最大血量变化、死亡冻结，
  以及内联后的字节码加载执行和不存在辅助方法调用。
- GameTest：`./gradlew runGameTestServer -DisDev=true -PacademyGameTests=academy:true_health_offset`。
  覆盖拒绝写入、tick 回滚、CTA/DM 连击、普通伤害、治疗、图腾、死亡取消、
  状态重载和完整衰减。
- 客户端烟测：仅在独立测试世界中添加 JVM 参数
  `-Dacademy.trueHealthSmoke=true` 并快速进入世界。
  TrueHealthOffsetClientSmoke 创建临时锁血实体，核对客户端同步及衰减，
  成功记录 TRUE_HEALTH_CLIENT_SMOKE_PASSED 后退出。正常启动不会启用。
