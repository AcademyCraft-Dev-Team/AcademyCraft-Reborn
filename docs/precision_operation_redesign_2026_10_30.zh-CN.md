## 方案核心：简化入口，保留明确的执行契约

### 目录分三层

- **常用**：按任务展示“选取目标、条件判断、等待、移动、转向、释放、能力动作”等操作卡和模板。建议每系默认约 8–12 张高频卡，准确数量通过任务测试确定。
- **进阶**：开放集合、循环、变量、局部锚点、持续控制、条件与资源管理。所有当前可见执行能力都能找到。
- **兼容**：已隐藏的旧类型与别名不重新塞回常用栏；旧图加载时仍能显示、编辑、编译，并解释建议的替代节点。

搜索同时支持中文名、英文名、别名、用途与对象类型，例如“最近、准星、抬升、停止旋转、金属、敌方”。条目显示用途、必需技能和对象类型，未学会与未开放使用不同状态。未开放的静态化入口默认不作为推荐动作；旧图仍显示明确状态。

### 按家族合并，避免万能节点

| 家族 | 设计 | 保留的差异 |
| --- | --- | --- |
| 数值常量、运算、比较、转换 | 现有统一入口继续使用，完善类型和运算模式呈现；旧专用 ID 保留兼容 | 整数、浮点、大整数的精度、转换与错误语义 |
| 目标与空间查询 | 统一目录卡片和术语，模式选择准星/附近/最近/最远/指定点 | 实体、方块、结构、位置、方向仍为不同强类型 |
| 集合与筛选 | 按“获取、筛选、排序、取项、组合”组织；可证明等价的心理旧节点提供迁移预览 | 有序性、重复项、空集合、随机取样时机与数量上限 |
| 条件与流程 | 一致的比较/分支表单，常用条件可一键插入原节点子图 | 数值条件、集合谓词、世界查询与有副作用动作分离 |
| 结构动作 | 三系采用一致的“移动/转向/回正/自转/释放”词汇和参数布局 | 单体持有句柄与群组动作的自动释放不同；三系权限、费用和施力方式不同 |
| 能力专属动作 | 每系保持能力身份；相近功能以家族卡归类，配置选择展开真实节点 | 电弧与链放电、电子束与扇面、印象操作与感官过滤等不因视觉相似而强并 |

第一阶段采用 UI 家族聚合，保存原 ID、codec 和端口。真正合成新运行节点须另外证明类型、费用、执行顺序与取消等价，再提供版本迁移。模式切换若导致连接不兼容，应说明冲突并保留原图，不能静默删线、丢配置或把集合偷转为单体。

已有“触发 → 动作”的默认用法属于现状，不能重新列为新增成果。新的易用性收益应来自：能找到该动作、理解默认目标、看到实际默认值，以及一键插入可靠模板。

## 文本与最简使用

统一采用“动词 + 对象”，端口名称回答“什么东西”，说明回答“做什么、默认取什么、结束后怎样”。常用参数给单位：格、格/秒、秒、角度；调试页再展示 tick、runtime、controlId 等实现信息。

| 当前问题 | 建议 |
| --- | --- |
| `tier` / `charge_tier` 暴露 wire 字段 | 分别用“提取档位”“蓄力档位”，配显示范围与效果 |
| “取得结构控制”让新手误以为每个动作都要先接句柄 | 常用动作直接提供已有默认选取；高级视图用“接管结构”并解释后续持有/释放 |
| “释放”容易被理解为删除、还原或立刻制动 | “结束控制”，明确结构继续自然运动；制动、自转停止和静态化分别命名 |
| 两类“随机实体”、两类“获取方向”同名 | 名称或副标题说明“从集合随机取一个”“从起点指向终点”等语义，按真实端口而非名字迁移 |
| 泛化的“失败/不可用” | 指出对象、原因和下一步；区分等待地形、对象失效、权限拒绝、预算不足、未开放 |

失败说明示例：“正在等待原版方块更新，准备窗口还剩 80 tick”“目标结构已卸载，控制已结束”“目标含不可控材质，改选目标或使用允许的能力”。可按正常 20 TPS 辅助显示预计秒数，但不能把它承诺为实际墙钟时长。具体显示值应取服务端真实规则，不再复制一份易过期的客户端常量。

默认输入采用任务相关规则，并在面板显示“未接线：使用准星结构/当前位置/视线方向”。一次性移动、传送和发射在开始时锁定目标快照；需要持续跟随的行为以明确模式或动作表达。省略输入不能省略技能、范围、材质、所有权、费用和服务端验证。

| 能力 | 高频模板或任务 | 应强化的能力特色 |
| --- | --- | --- |
| 矢量操作 | 抬起后转向并投出；偏转来袭投射物；观测后施加矢量 | 速度、方向、动量控制；高阶用户继续使用锚点与持有句柄 |
| 电击使 | 磁性目标搬运；感应后放电/链式放电；检测后充能 | 磁性条件、能量检测与电流路径；强制磁化单列条件和费用 |
| 空力使 | 布置自有喷口后移动/转向；汇聚后喷射；层流切割 | 喷口归属、朝向与有限推力；结束只清理本次拥有的控制 |
| 传送使 | 安全检测后移动自身、实体或方块/物品 | 空间安全、朝向与目标类型；本轮仍按已有同维结构适配边界设计 |
| 原子崩坏 | 目标选取后使用定点采掘束、电子束、扇面或原子喷射 | 射线、扇面、持续采掘的不同命中和消耗规则 |

| 心理掌握 | 支持性筛选后操作目标；守卫/寻路；潜入开始与结束 | 受控名单、支持类型、关系与观察视角；明确效果的开始和结束 |

模板首先展开为已有节点，保留查看、修改、保存和普通编译能力。建议先做 8–12 个高频任务模板，通过新手任务实测挑选；不是立即新增另一套不透明运行器。

预览分三个层次：编辑时展示类型和默认目标；运行前展示范围、成员数与资源估算；运行时显示“准备/等待/执行/完成/失效”及当前对象。客户端估算不能替代服务端授权，预览不能默认执行破坏或提取。

## 性能提升路线

当前证据支持的候选热点是重复编译、昂贵查询与摘要、精密界面的列表/视图/schema 重建；本轮尚未测量耗时排名，不承诺提升百分比。

1. **编译缓存**：先记录编译次数和分段耗时，再以图内容或修订、能力集合、编译器/迁移版本、扩展 fingerprint 为键做有界缓存。失败、技能变化、重载及扩展更新均有失效策略。不能只按程序 UUID 缓存。
2. **UI 版本缓存**：缓存目录、语言搜索索引、NodeView、schema 和布局；图编辑、配置模式、技能解锁、语言、缩放/字体与扩展变化分别失效。先复现旧漏绘，再验收缓存，不能把缓存设计当成已修复漏绘。
3. **查询工作量预算**：分别记录候选扫描、排序、结构形状/内容读取及执行耗时。摘要可按结构激活和内容版本缓存；未知覆盖不返回伪完整结果。
4. **数据求值语义**：只有可证明纯的常量子图适合复用。DATA 可能读取随机数、时间、共享变量或实时目标；不能把每动作缓存直接改为整会话缓存。昂贵查询共享只在显式采样/快照语义下开放，副作用前仍核验权限和版本。
5. **调度和同步**：保留会话、公平性、fuel、寿命和实际工作量边界；状态只在变化或有界采样时发送。VM logical tick、server tick、物理子步分别计时，不降低碰撞、控制或租约刷新频率来制造性能数字。

详细埋点、建议预算与 benchmark 场景见性能专项。当前 palette provider 为 0；扩展预设缓存是未来兼容项，不能误报为当前主要瓶颈。
