# 独角仙性能审计：优化前

以下为源码与模型结构检查，尚未用计时结果替代验证。具体耗时由同目录两套 fixture 产生。生产优化必须在特效角度和阻隔实现验收后、保存基线后开始。

## 模型和渲染

正式 Blockbench 几何为 113 个命名部位、320 个体块，加上烘焙根节点共有 114 个 `ModelPart`。当前 `setupAnim` 调用父类重置整棵树，再选择四个槽；随后 `applyLocomotion` 对三套肢体中的十八条腿和十八个胫部施加动作，实际只显示选中的六条腿。

原版 `ModelPart` 遇到 `visible=false` 会终止隐藏子树的绘制。因此并非每只独角仙每帧都画 320 个体块；108 种有效组合实际可见 84–132 个体块、30–51 个命名部位。优化应针对整树姿态重置、未选中的腿计算，以及远距离仍保留的细节几何。

| 分支 | 部位数 | 体块数 |
| --- | ---: | ---: |
| head 0 / 1 / 2 | 6 / 5 / 5 | 20 / 18 / 24 |
| torso 0 / 1 / 2 | 3 / 15 / 6 | 22 / 42 / 28 |
| limbs 0 / 1 / 2 | 19 / 19 / 19 | 44 / 50 / 44 |
| additional 0 / 1 / 2 / 3 | 1 / 9 / 3 / 2 | 0 / 16 / 6 / 6 |

候选措施为只复位选中的可动骨骼、只计算选中六足；公开的距离/动画相位策略接受实体无关参数，远距离降级动画频率和几何。共享 renderer model 必须在每个实体绘制前重置该实体全部受影响骨骼，不能靠“上次实体”全局状态或跨实体跳过复位。

建议详细质量范围到 16 格，16–24 格降低次要动作，24 格以上使用独立低模和较低动作采样频率。32 格附近已触及当前实体尺寸的原版距离剔除，因此不扩大现有剔除距离来强行展示低模。边界包含规则需由公共策略和测试明确，实际压力场景同时报告实体真实距离。

## 服务端实体

当前每只实体每 tick 两次验证召唤记录，`getSummon` 为布尔判断构造 `Optional`、复制记录，并在扫描各记录时重复 `UUID.toString()`。可复用只读 membership API 与一次 tick 内布尔结果，不改变召唤索引、注销和卸载语义。

传感器 `isCommandedTarget` 针对每个候选再查找周边独角仙；编队 `targetScore` 针对每个候选重新扫描 48 格同所有者实体。这些查询可以在一次 `findTarget` 调用内取得快照并建立目标计数/集合，保持相同扫描盒、友军判断、分数和选择次序，不跨 tick 缓存战斗结果。已经直接满足所有者指令的目标可在不需要查询传感器时返回。

蓝图字符串在热路径反复生成注册表 key 字符串，远程攻击每 tick 解析 `Identifier` 并查注册表，模块 tick 同样重新解析模块 key。适合在蓝图应用和存档读取时解析稳定 key、计算静态布尔标志与系数；扩展模块的 handler 仍通过公共注册表正常调用。未知或迟注册扩展需要保持既有降级语义，不能把每次动态注册表查询任意变成永久错误缓存。

跟随和战斗导航仍频繁请求路径，但降低导航请求频率会影响玩法，不作为第一轮优化。`super.tick`、命中判断、追踪炮更新、物理碰撞、资源 tick 和既有泳导航行为保持原时序。

## 网络与多人解释

每名玩家召唤上限十六只。实体注册 tracking range 为独角仙 48、炮弹 96，原版追踪换算乘十六后仍受玩家视距约束；独角仙更新间隔为两 tick，炮弹为一 tick。第一轮不改变这类网络和命中语义。创生的接触/销毁 VFX 向 128 格内玩家广播，压力测试应记录真实活动数量与资源回收，不能把 mock 所有者解释成八台完整远程客户端。
