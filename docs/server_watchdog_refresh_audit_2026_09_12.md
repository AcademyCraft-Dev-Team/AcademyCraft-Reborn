# 服务端看门狗崩溃与周期刷新审计（2026-09-12）

## 输入与已确认根因

报告：`C:\Users\Dusk\.codex\attachments\82a7d594-98e4-4a63-866a-3f139e21e408\pasted-text.txt`。崩溃发生于 2026-09-11 13:40:34，Minecraft 26.2、NeoForge 26.2.0.70。

主线程停在：

`PropsManager.tick → checkStructures → StructureManager.getStructureAt → fillStartsForStructure → ServerChunkCache.getChunkBlocking → managedBlock/parkNanos`

单个 tick 等待超过 60 秒触发 ServerWatchdog。这是主线程同步等待区块完成，不是报告证明了某个 Java 循环独占 CPU 60 秒。报告中的其他模组 mixin 名单不足以指认具体模组造成了区块任务迟迟未完成。

本地 Minecraft/NeoForge 源码确认：`getStructureAt` 遍历结构引用时会请求起点区块的 `STRUCTURE_STARTS` 状态；查询玩家当前已加载区块并不意味着被引用的起点也已加载。`getAllStructuresAt` 本身也通过会加载区块的路径查询。仅延长检查间隔或调大看门狗超时无法排除这类阻塞。

另外，`hasChunkAt` 在服务端检查区块持有者和票据级别，不等价于 FULL 区块数据已可立即取得。因此本次周期读取使用 `getChunkNow` 并直接从返回的区块读元数据或方块实体。
