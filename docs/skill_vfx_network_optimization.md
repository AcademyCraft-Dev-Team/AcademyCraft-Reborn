状态：核心优化及烟雾、未元切割事件迁移已实现；2/8/16 人派发、真实双客户端与 64/8 KiB/s 限速场景已完成。完整边界与结果见 [多人验收记录](skill_vfx_multiplayer_validation.md)。

## 已实施与验证（2026-09-08）

本次实现覆盖动能附加冲击波、粒机波形高速炮（含复用其实体的光束技能）、电浆炮，以及共用 VFX 图/粒子上传路径。下文其余章节保留为整体架构设计，不能把其中的后续优化项理解为全部已完成。

### 后续迁移与真实验证

Cloudroom、JetStrike 的烟雾和 DarkmatterCut 的短斩击已采用一次性参数事件；客户端独立播放并在可见范围外跳过绘制。切割使用复用四顶点网格和实例缓冲，烟雾透明度归零后回收。未元羽刃、矛、生物炮弹等有玩法职责的实体，以及其他动态电弧/光球仍待独立迁移，不包含在本轮完成范围。

普通、64 KiB/s、8 KiB/s 三个双客户端场景均完成；每轮双方各收到 1,589 个特效包，终态活动效果与待发更新为零。已核对游戏截图与实际 GPU 查询。没有迁移前基线和逐事件漏显率统计，不能把收包完整直接等同于零延迟或逐次无漏显。详见多人验收记录及其中的复现脚本。

### 运行时改动

- 新增公开的 SkillVfxService、类型化 SkillVfxState 和固定字段 SkillVfxPacket。冲击波只发送一次显示事件，不创建服务端 KineticShockwave。
- HighSpeedElectronBeam 与 Plasma 保留服务端技能逻辑，通过 broadcastToPlayer(false) 关闭原生实体广播；客户端使用不加入 ClientLevel 的轻量适配实体承接已有渲染器/图绑定。
- 开始、阶段变化即时发送；每 5 个物理服务端 tick 检查变化，普通状态每 20 tick 续传。客户端推演蓄力和电浆轨迹，并按实体年龄变化校正推进速率。
- 观察者按完整光束/反射段和电浆保守体积筛选；中途进入会收到完整当前快照，退出只隐藏本地订阅。当前候选玩家仍按维度扫描，尚未引入空间索引。
- 每观察者普通更新队列最多 256 项，同 effectId 合并，只保留最新状态；每 tick 最多发送 8 条普通更新，排队超过 10 tick 的更新过期。开始、阶段变化、命中、结束直接发送并撤销该效果的旧待发更新。
- 显示实例有独立编号、版本与有界终结记录；重复/旧快照不会覆盖当前阶段。短束开火与结束同帧到达时保留至少 3 客户端 tick 的闪光显示窗口。
- 电浆命中由 Plasma.impact() 发出独立事件，携带实际命中位置，不再根据客户端实体移除推断爆炸。
- VFX 图先处理生命周期/绑定并判断可见性，再模拟/构建/上传/绘制。离屏普通图降为约 5 Hz 粗模拟；外部管理的解析式效果仍遵守 frameVisible。辉光使用主绘制阶段的可见性结果。
- 电浆聚集、聚焦、弹体/拖尾和爆炸分别设置保守包围球，并保留远裁剪面需求；光束按线段提前剔除，冲击波按球体剔除。
- 图输出新增可选 bounds_scale。默认 0 保持自定义 shader 的原行为；已核验的电浆球体、光晕、烟雾输出使用 2.0，按实例球体剔除后才写入上传缓冲。
- 光束沿用原有静态网格和实例化，复用变换矩阵；图和粒子 CPU staging 缓冲按既有 GPU 容量增长，避免粒子数逐渐增加时反复分配。图输出缓存可见实例索引，减少第二次全量层匹配扫描。
- 没有修改技能伤害、反射、CP 消耗和碰撞算法；未改动工作区已有的伤害/CP 等其他任务内容。

### 电浆蓄力位置修复

## 1. 目标与结论

采用“服务端权威判定 + 特效事件/阶段快照同步 + 客户端独立播放”。

- 瞬时特效一次发送完整播放参数，在客户端自行结束。
- 持续特效发送开始、阶段变化、结束及必要的低频校正，由客户端推演连续画面。
- 伤害、反射、碰撞、方块破坏、CP 消耗、技能资格始终在服务端结算。
- 特效实例以独立 effectId 标识，不依赖对应实体已在客户端出现，也不随实体移除立即消失。
- 首轮复用现有 Misaka 注册与传输、VfxGraphManager 和已有渲染器，不另造网络连接或粒子引擎。

降低带宽需求可以缓解拥塞；远端观察者仍必须等待服务端消息，不承诺消除物理网络延迟。有限带宽下也不能同时保证无限事件完整播放、零延迟和零丢弃，需要明确降级规则。

## 2. 代码确认的现状

| 链路 | 当前实现 | 对方案的影响 |
| --- | --- | --- |
| 动能附加冲击波 | `KineticShockwave` 仅存活 4～7 tick，双方 tick 到期 discard；`KineticEnergyApplied.Server.spawnShockwave` 创建服务端实体 | 适合直接替换成一次性事件，移除纯显示实体 |
| 粒机波形高速炮 | `BeamVfxClient` 在实体入场时创建 `BeamVfx`；后者依赖 `hasFired` 和实体剩余寿命，实体移除即停止 | 创建、开火状态和删除的处理时机影响可见窗口，应拆开显示寿命 |
| 光束计时 | `currentChargerTicks`、`currentRayLifeTicks` 是两端本地计数；`RAY_FIRED` 单独同步；发射后默认寿命 15 tick | 客户端可能先走完自己的蓄力/衰减，再收到开火状态；需要权威阶段时间 |
| 光束移动 | 非持续、非保持蓄力分支在服务端施加微小随机相位抖动，注册 updateInterval(1) | 纯装饰抖动应转到客户端；是否产生每 tick 网络数据要实测，不能把 interval 当实际包数 |
| 电浆蓄力 | `PlasmaGeneration.Server.tick` 反复写入 `GATHER_PROGRESS` | 蓄力起点、速度、阶段足以推演，无需逐 tick 同步连续进度 |
| 电浆飞行 | `Plasma` 在服务端按固定目标和速度移动，客户端 tick 直接返回；目标、速度、4 tick 发射延迟没有作为完整轨迹发送 | 客户端应获得轨迹描述，直接平滑推演飞行 |
| 电浆爆炸 | `PlasmaVfxClient` 发现实体移除且本地已观察到 launched 才在 lastPosition 生成爆炸 | 可能漏播、在过时位置播放，且无法区分命中与离开跟踪范围等移除原因 |
| 跟踪配置 | 光束 clientTrackingRange(10)，冲击波 64，电浆 160，均 updateInterval(1) | range 的单位为区块，64/160 分别是 1024/2560 格的配置上限，实际受视距等限制；不能按 64/160 格理解 |
| 已有事件入口 | `SpawnVfxGraphPacket` 已能携带位置、方向、缩放、寿命、浮点参数，按距离发给附近玩家 | 可复用广播与客户端接入模式，但目前缺少 effectId、阶段时间、终止原因和持续状态恢复 |
| 现有跟随 | `ActiveEffect.follow` 的目标移除后停止；`SpawnVfxGraphPacket` 找不到目标时回退固定位置 | 新同步层需要可恢复的锚点解析，不宜继续把跟随实体生命周期作为特效生命周期 |
| 时间与渲染 | `ActiveEffect` 的显式寿命使用单调实时时钟；VFX 图逐帧模拟；仓库已有 TemporalRuntime | 必须区分播放寿命、服务端模拟年龄和时间能力效果，不能统一用本地 tick 或真实秒数替代 |

其中代码行为已核对；多人现象的具体占比尚未通过抓包、客户端事件记录和限速复现确认。

固定延迟本身通常只把开始、结束一起后移，并不必然压短显示时间。积压后集中处理、客户端卡帧、跟踪范围变化、阶段状态不完整和本地计时偏差，才是需要分别验证的“完全没看见”原因。不得仅凭表现认定网络包真正丢失。

Misaka 依赖源码的 `MisakaNetworkServer.send` 最终调用 `player.connection.send(new S2CPacket(packet))`，复用游戏连接。新事件包不能越过已经写入连接的积压数据；优先级和合并必须尽量发生在应用发送队列中。

## 3. 按同步语义分类迁移

| 类型 | 代表 | 同步内容 | 客户端职责 |
| --- | --- | --- | --- |
| 瞬时结果 | 冲击波、超电磁炮光线、斩击、短电弧 | 一次完整事件：几何、强度、随机种子、寿命 | 本地生成、衰减和销毁 |
| 固定或保持蓄力 | 粒机炮、电浆聚集 | 开始快照、阶段变化、取消/释放 | 按阶段起点推演；保持蓄力不得自行开火 |
| 连续束或附着效果 | 持续光束、武器效果、跟随光球 | 开始、变化量或完整校正、结束、入场快照 | 跟随锚点、插值、处理暂时不可见的宿主 |
| 可预测飞行 | 电浆弹体 | 发射起点、目标/速度、延迟、模拟年龄、必要校正、明确命中 | 推演轨迹；用服务端命中事件触发爆炸 |
| 真正参与玩法的实体 | 光束判定实体、电浆逻辑实体及其他实体化技能 | 保留服务端实体/逻辑及其既有玩法更新 | 渲染消费独立状态；是否仍需客户端实体按用途单独决定 |

首轮审计清单包括 `KineticShockwave`、`HighSpeedElectronBeam`、`Plasma`、`RailgunRay`、`ArcEffect`、`Smoke`、`GlowCircle`、`LightOrb`、`DarkmatterCutSlash`、`MagneticWeaponBlade`，并额外检查直接继承 Entity 的 `Arc`、`HighSpeedJetNozzle` 和各类投射物。不能只搜索 RenderOnlyEntity 子类，也不能根据类名删除其服务端逻辑：光束和电浆实际承担了攻击结算。

## 4. 统一协议与公开接口

建议新增以下职责，名称为设计草案：

- `org.academy.api.common.vfx`：`EffectType`、不可变类型化描述、`EffectAnchor`、`EffectHandle`、`EffectEndReason`。
- `org.academy.api.server.vfx`：`SkillVfxService.emit/start/update/end`，供技能和能力分类通用效果调用。
- `org.academy.internal.server.vfx`：活跃实例表、观察者集合、空间索引和发送预算。
- `org.academy.internal.common.network`：注册类型化特效包及编解码。
- `org.academy.internal.client.vfx`：实例状态机、时间估计、去重、补播策略与渲染适配器。

接口以 ServerLevel、世界坐标、可选实体锚点/施法来源为基础，不强制 ServerPlayer，方便精密操作程序及非玩家实体调用。发包接收者依然是 ServerPlayer。不要把伤害逻辑放进公共显示服务。

### 4.1 消息语义

| 消息 | 用途 |
| --- | --- |
| EMIT | 独立的一次性结果，收到即可播放，不需要先有 START |
| START / SNAPSHOT | 创建持续效果，或恢复其当前阶段；包含足够独立重建的状态 |
| UPDATE | 连续几何/位置变化；完整小快照优先，只有测得收益后才引入依赖基线的 delta |
| TRANSITION | 释放、开火、暂停、恢复等状态变化，携带新阶段完整参数 |
| END | 原因明确的最终结束，如完成、取消、命中、宿主死亡；本身不隐含爆炸 |
| HIDE | 当前观察者退出可见范围，只结束本地订阅，不标记全局效果终结 |

电浆 IMPACT 建议是独立 EMIT，关联父 effectId；即使客户端从未收到 START/LAUNCH，也能在正确位置播放爆炸。它与 END 使用不同事件去重键，避免先处理 END 后把爆炸当旧消息丢弃。

### 4.2 关键字段

通用信封包含：连接/世界会话代次、维度、effectId、revision、消息类型、效果类型、采样时间。维度及注册表版本等可放批次头，避免逐条重复。

- effectId 由服务端分配，生命周期内稳定；使用会话代次避免重连、换世界或数字复用污染。
- revision 单调递增；重复事件只播放一次，旧状态不得覆盖新状态。即便传输有序，入场快照和本地异步处理仍需版本保护。
- START/SNAPSHOT 携带阶段、阶段模拟年龄、推进速度或暂停状态、完整必需几何、可选锚点和回退世界位置。
- 短特效携带服务端发生时间、允许迟到时间、播放寿命；这些参数由受控效果类型决定，不让调用方无限延寿。
- 命中携带服务端实际坐标、法线、规模/等级和视觉变体；无需把伤害值或完整技能状态同步给观察者。
- 可选 predictionKey 只用于施法者的本地预表现和服务端结果对应，不替代权威 effectId。

全包一次应用必需参数后才创建渲染对象，避免用默认方向/默认阶段先播一帧。宿主尚未加载时先使用回退坐标，并在短暂有界时间内尝试重新绑定。

已终结实例保留有界去重记录以防旧快照复活；HIDE 不进入全局终结记录，重新进入范围时允许同一 effectId 恢复。换维度/断开清空实例、去重表、锚点等待表和预测状态。

### 4.3 编码与线程

优先使用注册的类型 ID、固定字段、可选字段位图、VarInt 和 float 参数。位置保留 double 或采用有明确原点的相对坐标，避免远坐标精度问题。随机种子重建装饰噪声和粒子，但反射、穿透、折线拐点必须使用服务端判定结果。

不要逐粒子、逐电弧细分点同步，也不要在高频消息里重复字符串参数名或 VFX 图 JSON。现有 SpawnVfxGraphPacket 保留兼容入口，逐步转交服务层；类型化实例协议独立演进，不让它继续膨胀成任意 Map 协议。

解码时限制批次条目数、路径节点数、长度、寿命与非有限数值；注册版本不匹配要在连接协商阶段明确处理。客户端实例表与世界访问统一切到客户端主线程，资源/GPU 操作沿用既有渲染线程约束；接入时核验 Misaka handler 的实际调度方式。

## 5. 迟到与时间处理

### 短特效：保证可感知，但限制补播窗口

- 冲击波等非持续攻击显示，在合理迟到窗口内收到后，从本地播放起点运行一个完整或压缩的短动画，不受原服务端实体删除影响。
- 初始调参建议：迟到容忍 500～1000 ms，补播保证约 100～150 ms 的可见时间，且不短于若干实际渲染帧；最终值通过录像评估确定。
- 超过窗口的旧事件明确过期，记录原因；不要在拥塞恢复后补播数秒前的整场战斗。
- 若同批到达 START/END，但包含未展示的一次性开火/命中结果，仍通过独立 EMIT 路径处理；持续蓄力可以跳过，结果动画按迟到策略保留。
- 补播只影响反馈，不重新造成伤害，也不伪造仍在持续的危险区域。

### 持续与飞行：恢复当前阶段

- 普通进度可按 `阶段年龄 = 已同步模拟年龄 + 自采样以来估计推进量` 计算，接收 TRANSITION 时切换阶段；年龄不可倒退。
- 使用低频服务端时钟采样与平滑偏移估计；RTT/2 只能作为近似，不假定链路对称。记录时间估计的不确定性。
- 时间能力下传输权威模拟年龄和推进速率/暂停状态；网络去重保留时间、接收队列年龄使用独立单调时间。不得假设 level.getGameTime 始终与实体推进速度相同。
- 电浆根据起点、目标、速度和 4 tick 延迟推演位置，最多推进到目标，不能无界外推。抵达预测目标时等待权威命中或取消，不提前生成最终爆炸。
- 不可预测转向或停时变化立即发送校正。普通校正可先试 2～5 Hz，连续瞄准束按角度/端点误差触发，并设最大静默间隔；频率以实测调整。
- 迟到的飞行阶段直接恢复当前进度；若 IMPACT 已到，不再从起点补飞。
- 渲染时间线必须支持阶段参数化或有界预热，VFX 图不能为补齐数秒历史而在一帧追算所有粒子。随机种子本身不保证不同帧率下逐粒子一致。
- 现有 ActiveEffect 实时寿命不直接承担受时间能力影响的权威存活判断；新增适配层明确控制暂停、恢复及清理。

施法者可在输入时立即播放蓄力、手部或镜头反馈，收到服务端结果后按 predictionKey 接管，拒绝或超时则收束。正式命中、反射和伤害保持权威；这一项在基础迁移稳定后加入。

## 6. 观察者选择、入场恢复与预算

### 6.1 按实际效果覆盖范围筛选

- 同维度过滤后，按光束各线段到观察者的距离、冲击波/爆炸包围范围、飞行路径及蓄力范围筛选。
- 只跟踪施法者会漏掉远处命中点旁的玩家；只按起点半径筛选会漏掉长光束末端。
- 用区块/网格空间索引选候选观察者，再做精确距离判断，避免每个效果每 tick 扫描所有玩家。
- 进入与退出阈值留滞回，避免边界来回抖动。几何发生大幅变化时立即更新观察者。
- 当前纯几何特效即便起点区块未加载，也可凭完整世界坐标播放；依赖地形采样的细节使用回退表现，不能因此强制加载世界区块。

### 6.2 活跃实例的订阅

服务端保存持续效果当前完整状态。玩家进入范围、重新跟踪、切换视距或完成世界就绪时，发送当前 SNAPSHOT；只恢复仍活跃的持续效果，不回放已过期瞬时效果。

END 发给已有订阅者；IMPACT 另外按命中点范围重新筛选。区分“效果终结”和“某观察者离开范围”，避免跨范围移动制造假爆炸。

快照与阶段事件从同一服务端状态版本生成。客户端只采纳较新状态；定期、低频、合并发送存活摘要或续租用于发现孤立实例，不逐效果每 tick 心跳。客户端可在租约失效后软淡出；恢复快照时重新接入，软淡出不等于全局 END。

### 6.3 每观察者有界发送队列

- 关键：START、TRANSITION、IMPACT、END；预留生命周期预算。
- 普通：持续位置/方向校正；队列内同 effectId 只保留最新版本，不能跨阶段错误合并。
- 装饰：远处小火花、烟雾等；允许合并、降低频率或丢弃。
- 批处理先试同 tick 合并、约 4～8 KiB 软上限，超过即拆包；关键事件不为凑满批次等待多 tick。
- 记录排队时长与字节预算；装饰不占用生命周期保留额度，预算恢复后不发送积压的旧校正。
- 极端过载时先限制新装饰/低价值实例的准入，为已经开始的关键实例保留结束能力；队列不得无界增长。
- 优先级只作用于尚未交给 Connection 的数据，不能突破同一连接中的区块等已有积压。也不应盲目增加应用层 ACK/重传进一步占用带宽。

客户端按距离和重要性调整粒子、折线细分和后处理成本，保留附近攻击的主轮廓。降渲染质量不等于漏接协议；保留轻量实例状态，以便回到视野后继续当前阶段。

## 7. 三个重点技能的落地方式

### 动能附加冲击波：最小试点

将 `spawnShockwave` 的实体创建改为 `SkillVfxService.emit`，发送中心、方向、最大半径、强度、寿命和事件 ID。把 `KineticShockwaveRenderer` 的环形畸变几何抽成独立渲染适配器，接入现有渲染阶段，保持原有外观。服务端范围伤害、击退和声音逻辑继续独立执行。

验收：不创建服务端 KineticShockwave；同一事件在目标客户端只播放一次；积压后到达但仍处补播窗口的事件可见。原实体注册可暂时保留，停止新建，避免首轮引入无关存档兼容变化。

### 粒机波形高速炮：分离阶段与判定

保留 HighSpeedElectronBeam 的服务端攻击、反射和取消流程。将 BeamVfx 的数据来源从实体引用改为独立 BeamVisualState：蓄力开始/保持、开火、连续束状态、终止。

开火消息一次携带服务端最终光束路径（包含反射）、宽度、侧向视觉偏移和播放寿命。短束独立衰减；持续束更新端点与阶段，伤害仍按原逻辑运行。装饰抖动在客户端按种子生成，不改变判定线。

复用现有 BeamCoreData/BeamGlowData 与 BeamRenderer，首轮通过适配器接入；VfxManager 已标为 deprecated，新增通用同步逻辑不要绑定到该旧管理器，图化迁移可以后续独立开展。

收益必须区分：若仍把服务端判定实体同步到客户端，只是让画面解耦，实体流量不会自动消失。确认没有其他客户端消费者后，再用当前版本支持的跟踪控制取消其网络可见性，或迁移到服务端技能运行时。不能把 updateInterval 调大当成已完成解耦。

### 电浆炮：阶段快照 + 轨迹 + 独立爆炸

START 捕获蓄力的固定原点和聚焦点，以及实际进度规则；保持当前蓄力构图不跟随后续玩家移动的语义。LAUNCH 携带最终阶段、轨迹与延迟。客户端用独立 PlasmaVisualState 绑定现有 charge/focus/projectile 图。

在 `Plasma.impact()` 权威命中点发出 IMPACT，完整给出爆炸位置与规模。取消、超时、移除与观察者退出分别处理；彻底移除 `plasma.isRemoved() => spawnImpact(lastPosition)` 的推断路径。

首阶段允许保留服务端 Plasma 作为逻辑实体，随后停止其非必要客户端同步；爆炸图的生命周期独立于弹体。声音若也接入事件，必须撤掉对应原广播并使用同一事件去重，避免双重音效。

## 8. 实施顺序和验证

1. 建立短暂诊断记录：effectId/实体 ID、生成时间、选中观察者、发送/接收、首次实际渲染、阶段、终止及未显示原因。分别计入网络等待、主线程等待、资产错误和渲染预算丢弃。
2. 实现统一 ID、类型化一次性包、客户端独立寿命与有界去重；迁移动能冲击波做对照试点。
3. 新增阶段快照和独立命中事件，先修正电浆移除误判，再迁移电浆全部阶段及粒机炮。
4. 加入观察者快照恢复、预算/批处理、低频校正；逐步迁移其余实体特效，取消冗余实体流量。
5. 根据测量结果加入施法者预测和更细的距离降级；不先承诺未经验证的压缩比例。

### 验证矩阵

- 同配置对比迁移前后：2、8、16 名玩家，单人连续释放与多人同时释放；分别压测三个重点技能及混合技能。
- 网络条件：正常、额外 RTT 100/200/400 ms、抖动、短时突发积压；每连接下行 128/256/512 kbit/s，并分别测试服务端总出口限制。模拟丢包用于观察传输恢复造成的等待，不假定应用消息会乱序。
- 场景：出生与删除同帧处理、开火包晚到、未见弹体直接收到命中、观察者只靠近光束末端/命中点、中途进入/退出范围、取消蓄力、切维度、重连、宿主未加载、重复/旧快照、客户端低 FPS、服务端低 TPS、时间暂停/恢复。
- 关键指标：包数与编码字节/秒、每观察者扇出、应用队列长度/年龄、接收到首次呈现 P50/P95、可显示事件漏播率、误爆/重复率、客户端帧耗时、活跃与孤立实例数量。压缩前协议量和实际出口字节分别统计。
- 漏播分母限定为“服务端确实选中的接收者、客户端收到有效事件、在约定时效和可见条件内”；服务端排队丢弃、过期、距离过滤和客户端降级另外报告，不能藏进分母外宣称零漏播。
- 预期验收：受控测试中短特效不因实体删除而漏播；电浆取消/失去跟踪不爆炸；未见弹体也能播放权威命中；旧快照不复活终结实例；伤害/碰撞/CP 语义保持一致。
- 带宽目标：冲击波从实体生命周期链路降为一个应用事件；电浆从连续进度/移动同步降为阶段事件和有界校正。具体百分比由基线决定。若总出口饱和仍超过关键事件预算，报告可承载并发上限与降级结果。

实现后按仓库规范运行 `./gradlew test -DisDev=true` 和两个 build 变体，并用独立服务器及至少两个客户端验证。自动化重点覆盖编解码边界、状态恢复、去重、迟到策略、观察者几何、队列合并与权威玩法回归。仅文档阶段无需启动构建或游戏。

迁移开关应按效果类型互斥选择新旧显示路径，禁止两条路径同时播放。保留可回退实现直至验证完成。当前方案本地提交状态以 Git 记录为准。
