# 精密操作性能与可玩性优化设计

日期：2026-10-30。审查基线为 `d42acb2d`，本文属于设计审计；没有实施 VM、节点、网络或编辑器重构，也没有新采集性能基准。当前节点逐项清单和显示/隐藏状态以[节点清单](precision_node_inventory_2026_10_30.zh-CN.md)为准，具体合并与文案映射见[合并和文本方案](precision_node_merge_text_2026_10_30.zh-CN.md)。本轮动能投掷降速由主任务另行实现，不把它计为本文性能方案的落地成果。

真实注册/资源加载后的库存为 342 个去重 ID：277 个目录可见、65 个隐藏；其中 189 个通用 ID 被七系复用，目录发生数合计 1476。这个数不能当作同一玩家会看到或执行的节点数。当前 `ProgramNodePalette` provider 为 0，下文涉及预设展开的缓存仅覆盖扩展路径，不是当前已测瓶颈。

## 1. 目标与边界

最简操作应能用“触发 → 动作”完成，目标、方向、时长只在有意义时展开；复杂用户仍能控制目标集合、锚点、条件、循环、资源、姿态和取消时机。减少常用入口数量，不等于删除执行能力或将不同对象都转换成“实体”。

本设计坚持四个边界：

1. UI 家族合并优先，旧运行 ID、类型端口、配置和执行语义先保留。候选列表更短不意味着运行量自动变小。
2. 客户端可给出解释和预览，真正的世界查询、权限、资源、结构激活和控制租约仍由服务端判定。
3. 取消只结束本次控制；已产生的运动、已持久提交的物资转移和已发生的世界破坏不能用“撤销”文案掩盖。
4. 优化前先测量。下列耗时、延迟和学习目标是建议验收标准，不是已经取得的提升比例。

## 2. 当前实现的证据与已有约束

| 位置 | 当前可确认事实 | 对设计的影响 |
| --- | --- | --- |
| `AbilityProgramManager.executeTriggered` | 逐槽匹配后调用 `definition.compile`；目前没有在该路径看到跨触发编译结果缓存。编译发生在 `consumeAutomaticRunBudget` 前。 | 重复触发的小图可能反复迁移、校验、解码配置和构建编译图。应先用计数器确认发生次数，再缓存不可变编译结果。 |
| `AbilityProgramDefinition.compile` / `ProgramCompiler.compile` | 执行迁移、验证、配置 codec 解码、动态 schema 解析、输入连接和控制流构建。 | 编译缓存必须包含图/能力/扩展版本，不能仅以 program UUID 为键。 |
| `ProgramVm.Session.runSlice` | 每个流程节点创建 `dataCache` 和 `evaluated`；同一动作依赖的数据节点在该动作内去重。`RETRY` 保留当前动作节点，醒来后重新解析输入。 | 有重复分配与查询的候选热点，但现有缓存作用域也保护了“每个动作重新取值”的语义，不能一概扩大。 |

| `structuresAround` / `structureDistanceTo` | 附近结构查询后会逐体再次检查施法者距离；距离函数也需要核对激活 runtime ID 和施法者范围。 | 查询合并可以减少重复几何工作，但不能删掉权限、范围或激活检查。 |
| `structureContents` / 群组磁性检查 | 可调用 `world().summarize(4096)`；材质筛选、磁性参与等可能对同体重复扫描。 | 内容摘要是按几何/内容版本缓存的候选；缺区块或超预算仍不能返回伪完整结果。 |
| `ProgramSessionScheduler` / `ServerProgramScheduler` | 默认最多 256 会话；会话 fuel、最大寿命和 TemporalRuntime 调度均存在。tick/keys 使用会话快照列表。 | 现有有界设计应保留；fuel 是节点执行额度，不是耗时保证。列表分配是待测次要项，不能据此优先重写调度器。 |
| 实际精密 UI `ModularProgramScreen.paletteEntries/visibleEntries` | 每次遍历目录并新建候选列表，再筛选可见性、入口唯一性和能力门槛；非空搜索词还解析本地化文本。存在 provider 时才展开 preset 并调用 `catalog.schema`，本次实际 provider 为 0。渲染和点击路径均会使用这些函数。 | 应按目录、能力和语言版本缓存候选视图与搜索索引，并为以后预设扩展保留版本键。不能只优化独立桌面 VFX 编辑器的 `NodePalette`，它不是本界面的实现。 |
| `ModularProgramScreen.nodes/view/renderCanvas` | `nodes()` 每次重新构造 NodeView 并解析 schema；画布循环所有边和节点，使用 scissor。 | scissor 解决像素裁剪，不会消除所有对象构建、布局、文字和边计算；优先缓存语义视图，再做保守的视口剔除。 |
| `ProgramEditorNodeCatalog.resolvedEntries` | 无扩展时可复用原 entries；存在扩展时会组装解析视图，`entries()` 还要排序。 | 扩展目录应按冻结 fingerprint 缓存；不能假定默认每次都有这个成本。 |
| `AbilityProgramManager.ResultPacket` / `ProgramRunTrace` | trace 最多 48 步、详情最多 120 字符；自动循环/生命触发通常每 100 tick 发 trace，其他路径为 20 tick，失败/首次等可提前发。 | 已有节流，不应重新设计成逐物理步发调试包；应测量等待节点重复 trace 是否挤掉关键状态。 |
| `AcademyProfiler` | 已有 zone、counter、线程采样及 250 ms 快照缓存；本次未在程序核心路径读到对应的细分埋点。 | 优先复用，避免另起一个每 tick 收集全图/全实体的昂贵监视系统。 |

这里的热点是代码证据支持的优化候选，不是已测得的主耗时排名。真正排序须用同一硬件、模组集合和场景的基准确认。

## 3. P0：先建立可解释、可测量的基础

### 3.1 观测项

在现有 profiler 中增加固定名称的 zone 与 counter，不将玩家 UUID、每个图 ID、动态端口值拼成无限增长的 zone 名称。默认关闭采样；开发采样开启时也使用有界聚合。

| 域 | 时间区间 | 计数/大小 |
| --- | --- | --- |
| 编译 | migrate、validate、decode/schema、link、总耗时 | compile 请求、成功/拒绝、缓存命中/失效原因 |
| VM | 每会话 slice、每节点族、resolveInputs、action apply | fuel、RETRY/YIELD、跨 tick 等待、重入拒绝、动作/补偿数 |
| 查询 | 实体候选、ray、结构近邻、内容摘要、来源查询 | 实际候选/测试/扫描格、结果数、覆盖不全/截断、复用命中 |
| 控制 | 准入、取得控制、提取/牵引/姿态步、清理 | 成员数、租约/操作 ID、更换激活、预算拒绝、有效保持 tick |
| 网络 | save/sync/execute/result/debug | 编码与解码耗时、字节数、重试/限频、revision 冲突 |
| 编辑器 | palette、schema/NodeView、布局、节点/边、文字、命中测试 | 分配数、可见节点数、目录重建、缓存失效、语言/字体代次 |

增加一次可导出的“运行摘要”，包含图修订、节点与查询计数、等待原因、终止原因和已消费资源。默认不带完整世界内容、NBT 或其他玩家敏感信息。

### 3.2 先修复并单独验收旧漏绘

现有接续记录明确：编辑器停留 140 tick 时，旧“浮点数 0”“构造向量”的背景/文字可能漏绘，端口与连线仍存在；根因尚未定位。本方案不能把“将增加缓存”写成“已修复漏绘”。

先建立固定图截图与交互复现：初开、140 tick、10 分钟、缩放/滚动、窗口失焦/恢复、字体/语言资源重载、插入/删除/撤销、不同 GUI 缩放和窗口尺寸。分别核对背景、文字、端口、边与点击区域。只有复现证据指向缓存/裁剪失效时再改相应层。

UI 缓存必须使语义模型和绘图缓存分离：缓存未命中时重建，不能静默省略已有节点；缓存代次丢失应退回完整重绘。严禁用隐藏旧节点或减小碰撞/选择区域来“消除”漏绘。

### 3.3 等待状态必须真实可读

把现有 `PENDING/RETRY`、完成、拒绝和取消区分显示：选区检查 → 等待原版更新/地形 → 转移内容 → 提取 → 已到位/动作完成。只显示真实阶段，不伪造百分比或 ETA。

- 等待期间保持同一操作 ID、同一结构/运行激活；不能重取准星、重新创建、重新扣费。
- 取消按钮先解释范围：“停止本次能力控制”；已提交转移仍由持久事务完成，结构与惯性保留。
- 原内容已改变时提示重新选择；不能自动恢复快照覆盖他人刚放下的方块。
- 草已正常清理而实心块尚未转移的失败，不可笼统提示“全部未改变”。取消在提交前后应有不同说明。
- 群组呈现逐成员结果与整体状态；不能把部分成员已受力隐藏成完全未执行。

## 4. P1：性能实施方案

### 4.1 编译结果缓存

缓存对象仅为不可变编译图与诊断，不含玩家、实体、世界、资源账户或控制句柄。建议键至少包含：类别、程序 ID/内容摘要、书/图修订、图 schema 版本、能力集合指纹、扩展 fingerprint、编译限制和迁移/编译实现代次。只用 UUID 或客户端自报哈希不足以安全命中。

保存、导入、能力集合变化、扩展注册/协议变化、迁移代次变化时失效；玩家离线和服务器停止时清理相应索引。采用条目数与估算字节双上限的 LRU，不以“只有 10 槽”为由保留所有历史版本。编译失败可对相同修订短暂缓存，但编辑或新能力解锁应立即重新校验。

自动触发可先查看启动预算再做昂贵编译，避免预算已用完仍编译剩余候选；生命阈值触发的锁存与当前轮转公平性必须保留。是否把预算内未执行事件排队属于新玩法，需显式策略，不能借优化悄悄改变现有事件丢弃/触发语义。

动作执行仍即时验证类别、能力、资源、PVP/领地、距离和控制权。编译命中永远不等于获得操作授权。

### 4.2 数据求值与查询复用

**`DATA` 角色不等于纯函数。** 随机、当前目标、位置、时间、共享变量读取均可能变化。直接将当前每动作 `dataCache` 扩大成整帧/整会话缓存，会改变旧图语义。

先引入求值特征元数据，并让未知扩展默认不可跨动作缓存：

| 特征 | 建议复用范围 | 失效条件 |
| --- | --- | --- |
| 编译期纯常量子图 | 编译图生命周期 | 任何输入、配置、能力/扩展代次变化 |
| 本次触发快照 | 一次 invocation | 新触发；显式刷新；旧图继续保留旧采样语义 |
| 本次采样查询 | 指定采样节点/本 tick | 起点、方向、参数、维度、激活/内容版本、世界变化或权限变化 |
| 随机/时间/共享变量 | 默认每次使用 | 只有用户显式“取样并保存”时才锁定 |
| 世界动作/资源/控制 | 不缓存执行结果充当授权 | 每次 apply 前重验；等待只持有准确操作句柄 |

对同一结构的材质摘要可以按 `(dimension, stableRef, runtimeId, contentRevision)` 复用；姿态或距离还必须考虑 pose revision 与查询起点。未知覆盖与失败结果不能长期缓存成空结构或“非磁性”。缓存中仅保存有界摘要，不复制 NBT。

结构查询与实体查询保持对象类型和范围约束；共享查询计划可将同一采样下“附近 → 过滤 → 最近”组织为一次候选枚举，再保留现有稳定排序与类型检查。不能把输出 limit 当作扫描上限，也不能为快取最近对象提前跳过必要候选却声称结果仍全局最近。

### 4.3 预算与可恢复等待

保留 fuel，再为重查询增加可观测的工作量预算：实体候选、方块扫描、结构内容格、形状测试、网络 trace 字节。预算同时有玩家额度、服务端总额和单操作硬限，按真实 server tick 结算；控制命令则沿其物理时钟执行。

长查询采用专用 continuation，保存确定的游标、来源版本、操作 ID 与已消费资源；只有重验通过才续跑，不把不完整结果伪装成完整集合。旧同步查询 API 可以保留原有失败语义，新异步查询应返回 `完整/截断/等待/不可用` 等明确结果，不能仅用空集合表达所有状态。

`RETRY` 等待物理动作时，可订阅其状态变化或使用可预测的下次唤醒点，避免每次醒来重做整组昂贵准备；物理服务仍独立按必需子步更新。不能因等待 UI 不可见或程序没有继续走图，就停止物理控制、租约维护或持久事务恢复。

必须区分三种时钟：TemporalRuntime 驱动的 VM logical tick、实际服务器 tick 的预算/去重、物理子步的 dt。不能通过统一降低 tick 频率来提速，也不能再次把子步数当成完整保持 tick。

### 4.4 编辑器缓存与局部更新

1. 按 `(目录/扩展 fingerprint, 能力集合, 语言代次, 预设提供者代次)` 构造候选快照。缓存 label/description/关键词的小写搜索文本及默认 schema；输入搜索词、组选取、已有入口状态变化时才重筛。
2. 以图修订维护 node ID 索引、边邻接表、已解析 schema 和 NodeView 语义部分。平移/缩放只变换几何，不重新解码全部配置；修改配置仅重建受影响节点和端口/连线。
3. 缓存节点包围盒和端口位置；先保守剔除完全离屏节点、远离视口的边，再绘制。跨视口的长边和选中/拖动对象不能被错误剔除。
4. 文字测量按文本、字体/语言代次、字号与缩放策略缓存。资源重载统一失效；不能缓存绑定到已释放纹理、旧字体或临时 Canvas 的对象。
5. palette 已按可见行绘制，应保留这种方式；优化重点是候选构造，而不是声称“第一次实现虚拟列表”。

节点家族 UI 与这里联动：一个 family 只展示一张卡，但展开的具体模式仍有独立 schema、技能门槛和说明。按连线类型推荐模式时复用兼容性索引，不能为了减少 schema 解析把所有端口改成 `ANY`。

### 4.5 网络、trace 与调试

书保存继续使用 revision 冲突检查；短期先做客户端编辑防抖和只在显式保存/必要时发送，不为每个拖动像素传整本 1 MiB。后续若引入增量保存，仍要保留全量同步与摘要重校验的恢复路径，并明确协议版本。

等待同一节点的重复 trace 可压缩为“阶段、持续 tick、最近原因、重复次数”，优先保留进入/退出和首个失败，不让 48 步全被同一等待填满。编译失败、运行失败、超时和用户取消分别呈现；日志限频不能隐藏首个错误。

详细调试按正在观察的程序订阅，节流并有字节上限；断开订阅、离线或界面关闭后停止。物理姿态继续复用现有同步机制，不能为了节点面板再发一套每步全结构姿态包。客户端预览没有操作权限，不执行“假扣费”或影响服务端目标。

## 5. 可玩性：常用两节点，复杂流程逐步展开

以下是建议体验与模板验收，不表示本批已经新增节点。每个模板必须用现有/计划的真实类型 schema 编译验证；无法安全生成的模板不应出现在“即用”列表。

### 5.1 全类别共用的易用入口

| 操作层 | 最简体验 | 进阶保留 |
| --- | --- | --- |
| 触发 | 按键触发、手动运行优先；首次进入给一个可运行示例。 | 循环、运动、生命阈值、聊天等自动触发保持独立语义；频率、锁存、冷却/资源条件可见。 |
| 目标 | 默认目标卡写清“准星实体/结构/方块”，连入目标后自动让位。 | 附近集合、选取点最近、排序、筛选、排除、集合运算、foreach；不能混淆实体与结构。 |
| 数值与向量 | 简单数值可在动作内直填，方向/位置有世界/局部标识。 | 类型明确的变量、向量运算、显式坐标/旋转基准；不隐式把位置当方向。 |
| 条件与流 | 常用条件直接用可读标签；失败定位到具体节点和端口。 | 分支、循环、等待、终止本图继续保留；“终止图”与“释放结构控制”不是同一按钮。 |
| 输出与调试 | 成功、等待、失败和资源消耗有简洁状态。 | 引用/句柄/集合/receipt 能展开查看，原始错误码放详情，保留运行追踪。 |

“取默认准星”应在动作首次开始时锁定具体目标，后续 `RETRY` 使用同一目标。需要持续跟随或重新选择的玩法必须显式选择“跟随/实时采样”，避免玩家只是转头就误控另一结构。目标失效默认停止本动作，不自动替换成最近的其他对象。

### 5.2 物理结构三系的区别应成为玩法

| 能力 | 建议基本模板 | 必须保留的设定和反馈 |
| --- | --- | --- |
| 矢量操作 | 按键 → 物理化选区；按键 → 牵引/发射准星或本人当前结构。更完整的模板明确展开创建、调整、发射/释放。 | 有限力、质量/距离与控制预算；释放后保留惯性；新标准/里程碑速度由共享技能函数读取，UI 不保存过时硬编码。 |
| 电击使 | 按键 → 牵引磁性结构；附近集合 → 磁性/来源筛选 → 群组移动。 | 磁性参与、强制磁化的额外条件、材质与资源限制；不把普通材质默认当磁性。准备与持续牵引费用分开呈现。 |
| 空力使 | 按键 → 操作本人喷口支持的结构；喷口方向 → 持续推力/力偶旋转。 | 喷口、支撑格、归属、压缩空气与有限推力；推进窗口结束不等于自动到点刹停。仅恢复本会话仍拥有的喷口状态。 |

单体/群组可以共用一个家族入口，但群组移动默认仍是每体各自初始质心加位移；不能悄悄变成绕共同中心公转、刚性编队或强制瞬移。共同中心旋转、轨道/编队若要增加，属于新动作，应有明确的物理预算和模板，不通过 UI 复用旧 ID 冒充已经支持。

结构预览建议显示整结构轮廓、质心/局部锚点、方向、位移和受力/旋转基准。客户端只能估计的阻挡使用“待服务端检查”；地形未加载时不画成确认畅通。停止/释放必须易于找到；“安全还原世界方块”目前仍非已开放基本节点，不应放入可运行模板承诺自动落地。

### 5.3 其他能力不能被结构方案遗漏

| 能力 | 可玩性优化方向 | 保护边界 |
| --- | --- | --- |
| 传送使 | 自身/实体/结构/方块物品的目标与落点卡片；同维落点安全检查及朝向预览；“按键 → 传送”模板填默认对象。 | 身体/结构占用体积和方向、加载范围、归属/维度必须校验；跨维结构迁移仍是后续，不能只靠目标列表放开。 |
| 原子崩坏 | 束、扇形、采掘和喷流等现有动作按任务和影响形状展示，提供准星/方向默认及攻击路径预览。 | 命中遮挡、PVP/破坏权限和真实射程；预览不能代替服务端路径破坏验证，不能把“采掘”合并成无条件范围删除。 |
| 未元物质 | 相态查询、分解对象、切割、甲虫和领域等组成简短任务模板；数据条件与世界动作分层。 | 相态、所有者、资源与召唤生命周期保留；不因共享目标 UI 就获得三系结构控制权。 |
| 心理掌握 | 名册/入侵/当前目标、存活/敌我/可控筛选及守卫/解除控制模板；用目标状态解释不能执行的原因。 | 入侵、控制支持度、目标权限、解除自身控制与全图终止分开；不得默认扫描并控制所有玩家以简化图。 |

### 5.4 模板与渐进学习

默认页只呈现“常用动作、常用目标、流程”三组；完整目录和兼容节点仍可搜索。按当前能力、已学技能和已连端口推荐；锁定项可见原因，默认不挤占常用列表。别名索引支持“扔/发射”“移动/牵引”“转向/旋转”等常见搜索，但实际节点名保持一致。

建议首批模板：准星动作、按键持续牵引、创建后人工确认发射、附近最近目标、附近集合筛选并逐个操作、资源不足时停止、目标失效时释放、同维传送安全检查、心理掌握守卫。模板插入后展开成可编辑的真实图；不能留下不可理解且无法局部修改的黑盒宏。

基本图不要求先理解 `StructureRef/runtimeId/controlId/receipt`；进阶视图仍展示对象身份、控制拥有者和精确失败详情。默认值必须能在节点卡上读出，例如“目标：准星结构”“方向：自身朝向”“持续：1 秒”；不要让重要行为藏在 tooltip。

## 6. 验收、测试和实施顺序

### 6.1 设计验收目标（尚未测得）

| 范畴 | 验收建议 |
| --- | --- |
| 入门 | 不查外部文档，首次玩家 2 分钟内完成一个“触发 → 动作”并能解释目标和取消；常用模板不要求先手工构造常量/方向/引用。测任务完成率和误操作数，不只数 UI 节点减少量。 |
| 旧图兼容 | 清单中每个旧运行 ID/有效配置/连线图均可载入，保存往返与旧执行语义一致；UI 合并不丢节点、端口、能力门槛或附加配置。 |
| 编译缓存 | 同一修订连续 100 次触发最多 1 次有效编译；每类键失效后首次重新编译。禁用/移除技能、扩展变化、编辑配置和图迁移反例必须拒绝错误命中。 |
| 等待 | 同一动作 100 次轮询保持一个操作/结构激活；资源仅在原收费点扣一次；取消后旧图不能释放后继控制；超时不覆盖新放置的源格。 |
| 查询 | 仅显式同采样快照可共享一次候选枚举。移动/破坏/分裂/卸载/瞬移/权限改变后不得返回过期授权或伪完整结果。 |
| 编辑器 | 128 节点/256 边，正常静止帧不重建全部 schema/目录；语言、资源和图变更能精确失效；140 tick 与 10 分钟都无漏绘/错命中。 |
| 可观测性 | 每次预算拒绝都能定位到玩家/图/节点族与工作量，默认日志有界；不要求公开其他玩家隐私目标值。 |
| 性能阈值 | 先记录基线 P50/P95/P99、分配和 GC；建议从“精密程序额外服务端 P95 ≤ 2 ms、P99 ≤ 5 ms，128 节点编辑器自身 UI 工作 P95 ≤ 2 ms”作为参考目标，在明确硬件/场景后校准。它们不是当前性能承诺或玩家 CPU 通用保证。 |

### 6.2 最少基准矩阵

1. 空图、2 节点、32 节点、128 节点；纯代数、随机/共享变量、每动作查询、显式一次采样各一组。对照语义后再比较分配和耗时。
2. 1/8/32 个玩家，各 1/4 个频繁自动触发，混合循环/聊天/生命/移动；忙闲图混合。达到 256 个挂起 VM 会话后再受理第 257 个，确认明确拒绝、公平性和清理，不能无界排队。
3. 密集实体、多个物理结构、重复材质/来源筛选；分别记录扫描量、结果量与权限过滤。测试范围边界、空/未知、卸载和高复杂形状。
4. native 与 Sable/Create/航空学混装；1/8 成员，多个玩家争用，租约更换、喷口移除、结构分裂、死亡/断线/换维。后端达上限时预期安全拒绝，不强行构造超过其容量的“性能通过”。
5. 编辑器 1280×720、1920×1080 和宽屏；低/高 GUI 缩放、离屏大图、10 分钟停留、拖拽/连线/撤销、语言/资源重载、窗口最小化/恢复。
6. 模拟延迟、重复包、保存 revision 冲突、调试订阅关闭、整本满尺寸；客户端不能通过降级/旧类型 ID 绕过服务器检查。

基准固定 JBR、GC、硬件、运行目录、模组版本、图摘要、种子和事件脚本；预热后采样，另保留冷启动/首编译数据。Profiler 开/关各测，避免把采样开销当真实改进。无输出结果或全被预算拒绝的运行不能作为“高吞吐”成功。

### 6.3 落地阶段

| 阶段 | 内容 | 依赖与完成标志 |
| --- | --- | --- |
| P0 | profiler 与基准、旧漏绘复现、准确等待/失败/取消说明、目录版本与旧图兼容测试。 | 先有真实清单；记录所有基线，不先承诺降幅。 |
| P1-A | UI 家族/模式、可读默认值、候选/语言搜索缓存、NodeView/schema/布局缓存。 | 与合并文案方案同批；旧 ID/图不改，漏绘回归必跑。 |
| P1-B | 严格版本键的编译缓存、自动预算前置检查、同采样查询摘要、trace 等待压缩。 | 保留权限与原采样语义；缓存失效、重试/取消、费用、扩展兼容反例通过。 |
| P2 | 工作量调度、查询 continuation、显式实时跟随/采样节点、有限的模板推荐、可选增量同步。 | 新状态/API/协议版本单独设计；公平性和多人/混装压力实测通过。 |

每阶段都交付可独立回退的代码、兼容测试与机器报告。没有证据表明提高现有预算上限、降低碰撞精度、减少物理控制步或取消权限检查是本方案的一部分。旧 64 体真实世界长期压力、硬中断全矩阵、编辑器历史漏绘等事项仍需其专项实际验收。
