# 矿物探测：轮廓显示与玩家周边扫描重设计

日期：2026-09-29。状态：上一轮改动回退后，已按本方案完成实现；当前轮廓按后续反馈加粗到约 3 像素。

## 1. 本轮处理与设计目标

开发开始前，`MineDetect.java` 已恢复到上一轮修改前的仓库版本。后续实现从该版本重新开发；之前的崩溃与能力存档修复独立保留。

新方案必须同时满足三项要求：

1. **显示矿物的屏幕轮廓**：斜视单块矿石时，只有投影外轮廓，不出现立方体内部的棱线；矿脉相接处自然连成轮廓。
2. **从玩家身边向外发现**：玩家脚边、头顶、背后以及区块边界另一侧的矿物优先完成扫描，并立即进入显示缓存。
3. **完整保留范围内结果**：取消上一轮的 96 个矿物上限。性能预算约束扫描、缓存更新和上传工作量，不截断可显示矿物的集合。

保留现有球形扫描范围：默认半径 64 格，对应熟练度里程碑提高到 80 格。耗能、开关与服务端能力规则沿用现有逻辑。

## 3. 显示方案：实心遮罩 → 屏幕轮廓

### 3.1 绘制流程

1. 从矿物缓存取得当前视锥内的分区网格。
2. 将矿物的实心几何绘制到独立的颜色／覆盖率遮罩，使用独立深度附件。忽略地形深度，使被山体遮挡的矿物仍能显示；矿物之间使用正常深度比较。
3. 后处理提取覆盖区外侧约 3 个物理像素的边界，再合成到场景。相邻不同矿种可保留颜色分界，同种矿物相接处不产生内部格线。
4. 每帧按当前相机重新栅格化遮罩，复用已上传的网格；相机移动不触发全量 CPU 网格重建。

可用覆盖率膨胀减去原覆盖率提取外轮廓；边缘颜色从邻近有效矿物像素取得。不得通过立方体法线变化重新画出三条内部棱线。

完整方块使用实心方块面；同种相邻方块删除共有面，允许合并共面的面片。非完整方块使用缓存的模型／形状几何；这部分需要针对实际模组矿物验证。矿脉保持真实几何，不以包围整个矿脉的大方盒替代。

同一屏幕像素被多块矿物覆盖时采用深度确定的轮廓颜色，避免透明度反复累加产生刺眼亮点。完全被其他矿物投影覆盖的矿物仍在缓存中，随视角改变自然显露；“完整保留结果”不意味着把重叠矿物的所有内部边缘叠画出来。

### 3.2 观感参数

| 项目 | 初始设计值 | 调整原则 |
| --- | --- | --- |
| 轮廓宽度 | 约 3 个物理像素 | 根据后续“线条不够明显”的反馈加粗 |
| 不透明度 | 0.8 | 保证暗处可读，不采用高亮反复叠加 |
| 颜色 | 按矿种稳定着色 | 降低饱和度；煤矿采用可读的灰色 |
| 光晕、脉冲 | 默认关闭 | 先验证清楚且不晃眼的静态轮廓 |
| 内部填充 | 默认不显示 | 遮罩内部只参与计算 |

这些是待实机调整的初值，不是已验证效果。独立遮罩不复制主场景深度；不直接套用现有宽范围 Bloom。复用 Academy 现有渲染资源创建、窗口缩放和释放方式，确保原版实体发光与其他能力效果正常共存。

## 4. 扫描方案：围绕玩家的三维距离优先队列

### 4.1 首次开启

建立两类任务：

- **身边快速任务**：半径 8 格，使用预先计算并按三维距离排序的偏移，小批量读取已加载位置。每批命中立即发布；本 tick 完成的结果可在下一次绘制中出现。
- **外围补全任务**：按 `8–16 → 16–32 → 32–64/80` 的距离带扩展。使用分区与小扫描块组织数据，优先级按玩家到任务包围盒的三维距离计算；任务内部继续从近处开始。

小扫描块建议为 `4×4×4` 或 `8×8×8`，可以中断续扫。分区索引采用 `16×16×16` 区块段。先用方块状态调色板判断是否可能包含矿物，排除确定不含目标的区块段。不得等待整个球形范围或整根区块柱扫描完毕才显示附近结果。

扫描、结果发布、网格生成和 GPU 上传均保留“附近优先”，否则只优化扫描顺序仍会被后续队列拖延。

### 4.2 玩家移动与范围补全

- 玩家跨过方块坐标时更新距离优先级，及时插入新覆盖的身边任务；已完成区域复用缓存。
- 使用待扫描／扫描中／已完成状态和去重索引，移动不会反复清空队列或重复排入同一任务。
- 身边待办完成后继续向外推进；为较早排队的外围任务保留少量处理份额，避免轻微移动导致远处永远扫不完。
- 保留仍有效的旧缓存，新结果逐批并入；范围变化时只增删受影响区域。
- 只读取客户端已加载区块，禁止扫描触发同步加载。新区块到达后按当前距离加入队列。
- 传送和切换维度时优先重建身边任务，旧维度任务通过版本号失效。

目标是在区块已加载的前提下，让半径 8 格内的矿物在开启后的前 1–2 个客户端 tick 出现。该目标需要在测试硬件上实测；预算到期时仍分批推进，不通过一次大扫描强行兑现时限。

## 5. 数量与性能：保留结果，摊平工作

### 5.1 显示数量

范围内识别出的矿物全部存入分区缓存，不设 96、128 等全局显示数量上限，也不按价值排序淘汰普通矿物。每帧绘制视锥内所有有效缓存网格，地形遮挡不用于剔除矿物。

空间范围、已加载区块集合与紧凑的分区存储约束缓存规模；待办队列按分区去重并限制并发快照数量。负载过高时推迟尚未完成的更新，保留已有有效显示，优先推进附近变化。矿种筛选若以后加入，应作为用户明确选择的显示功能。

### 5.2 各阶段预算

| 阶段 | 执行位置 | 控制方式 |
| --- | --- | --- |
| 身边扫描、外围数据快照 | 客户端主线程 | 共用时间预算，小批次检查；初始目标约 1 ms/tick |
| 外围匹配、可纯计算的网格生成 | 1–2 个后台工作线程 | 只使用不可变快照，有界任务队列 |
| 结果合并、缓存失效 | 客户端主线程 | 批量合并且计入主线程预算 |
| GPU 上传 | 渲染线程 | 限制单帧重建／上传工作量，附近优先 |
| 轮廓绘制 | GPU | 复用分区网格，实心遮罩、横向膨胀、纵向膨胀与边缘合成 |

预算包含快照创建、结果合并和排队维护；不能只给读取方块的循环计时。单次操作可能造成短暂越界，必须在剖析中记录峰值，必要时继续缩小任务粒度。

缓存每个方块状态的矿物判定和颜色，绘制热路径不再逐矿物查询世界、生成 AABB 和颜色数组。GPU 对象只由渲染线程创建和释放。涉及世界、模型或资源管理器的数据须在其所属线程准备；后台只处理已明确不可变的数据。

### 5.3 正确失效

- 方块变化：移除旧结果并写入新结果；重新生成该小块和涉及共有面的邻居边界。
- 区块卸载／离开范围：释放结果及网格；范围边缘按玩家的实际球形距离裁剪，不能将整个区块段都算作有效范围。
- 技能关闭、退出世界、维度变化：取消当前任务代际并释放资源。
- 标签、模型、资源重载：更新判定／几何版本，重新处理相关缓存。
- 后台结果携带维度、扫描代际、区块段和数据修订号，过期结果不得覆盖更新。
- 低频分区复核补足未经过普通单方块更新通知的变化；区块整体数据替换应主动使对应结果失效。

## 6. 建议的代码拆分

| 组件 | 职责 |
| --- | --- |
| `MineDetect.Client` | 技能状态、熟练度范围和生命周期入口 |
| 矿物扫描调度器 | 玩家附近优先、快照、有界任务队列与版本控制 |
| 矿物分区缓存 | 命中位置、颜色、脏区与增量更新 |
| 矿物轮廓渲染器 | 分区网格、独立遮罩、屏幕轮廓与资源释放 |

优先把技能内部职责分开。可复用的遮罩渲染方法遵循现有 `org.academy.api.client.render` 层的资源管理规范；矿物识别和距离策略留在技能实现侧。参考项目与当前 Academy 的 Minecraft／GPU API 有差异，代码需要按本仓库接口实现。

## 7. 实施顺序与验收

1. **轮廓原型**：使用固定测试矿物，先在游戏里验证单矿石、相连矿脉、遮墙和多个矿种的真实轮廓，拍摄斜视截图确认无内部棱线。
2. **周边扫描与完整缓存**：接入三维近处优先和逐批发布，验证开启、移动、上下高度与跨区块边界的响应。
3. **缓存和预算**：接入分区网格复用、增量失效和外围后台计算，按采样数据调整预算。
4. **压力与兼容验证**：检查大量矿物、资源重载、窗口变化和其他轮廓效果并存。

| 验收项 | 方法与通过标准 |
| --- | --- |
| 真轮廓 | 斜视单块没有内部棱线；同种相接矿脉无方格网；遮墙后仍可见 |
| 身边响应 | 玩家上下前后各 2、4、8 格布矿，覆盖负坐标及区块边界；记录第一条和全部近处结果出现时间 |
| 数量完整 | 构造超过 10,000 个目标矿物的测试场景，扫描完成后的命中集合与预期集合一致；普通矿物不会因远处高价值矿物而消失 |
| 移动与更新 | 步行、飞行、传送、挖矿、放置、区块替换和维度切换，不全屏清空重扫，不残留已移除矿物 |
| 性能 | 分别记录快照、扫描、合并、网格上传与 GPU 阶段；比较关闭／开启时的帧时间中位数、P95 和峰值，以及内存与显存 |
| 资源生命周期 | 反复开关、重进世界、改变窗口大小和资源重载，无持续内存增长与无效 GPU 资源访问 |

必要的自动化测试覆盖三维优先顺序、逐批发布、移动去重、外围任务继续推进、方块替换与过期后台结果拒收。按仓库要求执行 `test -DisDev=true`、开发版构建、发布版构建以及 `runClientDev` 入世界验证；主菜单启动成功不算视觉验收。

## 8. 实现对应关系

- `MineDetect.Client` 负责能力状态与范围，委托 `MineDetectClient` 管理客户端生命周期。
- `OreScanCache` 使用半径 8 格的三维距离有序偏移，外围以 8 格小区域向外补全，每批最多读取 64 个位置；移动时保留有效缓存，另有低频复核。
- 方块状态调色板排除确定不含矿物的区块段；实时世界读取与形状获取均在客户端主线程完成。
- `OreGeometry` 保存不可变颜色与形状，`OreMesh` 在两条后台线程上生成网格，同时最多有八个待处理／运行任务；结果按区域身份和修订号校验。
- `MineDetectRenderer` 复用区域 GPU 缓冲。球形范围完全覆盖的区域只画外表面，跨范围边界的区域额外绘制必要封口，避免移动时被裁掉的邻接矿物留下空洞。
- 轮廓使用独立深度与颜色遮罩，3 像素边缘由横向、纵向可分离膨胀生成；不读取地形深度，不加入 Bloom 或脉冲。
- 方块变化、区块加载／卸载、标签／资源重载、退出世界和关闭客户端均接入缓存更新或释放。

非完整矿物使用方块提供的 `VoxelShape` 重建实心外形。具有贴图透明孔洞或自定义渲染器的第三方矿物，仍需分别验证其外形兼容性。

可重复实机验证入口：`tools/vfxgraph-editor/scripts/mine-detect-client.init.gradle`。它在 `run/mine-detect-client/saves/railgun` 的独立测试存档中构造场景，验证附近响应、12,288 个矿物的完整保留、挖除／放置、资源重载与反复开关，并把截图和性能记录写入 `build/mine-detect-validation`。该入口只能用于可丢弃的测试存档。

## 9. 客户端探测半径设置（2026-09-29）

数据终端 → 技能设置 → 矿物探测 → 技能高级配置，新增“探测半径（格）”滑块。

- 取值 8–80 格，步长 1 格；选择的是以玩家为中心的球形半径。
- 默认设置 80，实际使用 `min(客户端设置, 当前熟练度上限)`：普通 64 格，第二里程碑后 80 格，保持旧配置的原有行为。界面注明熟练度范围上限。
- 拖动实时更新内存中的设置，下一客户端 tick 更新扫描与轮廓裁剪；松开鼠标写入客户端 `config/academy-client.json` 的 `config.academy.mine_detect.scanRadius`。方向键每次调整 1 格并保存。
- 缩小范围时立即按新半径裁剪显示，缓存分批回收；扩大时从玩家附近继续补齐，复用有效缓存。不会因为调整范围恢复数量截断或改变附近优先扫描。
- 配置缺项默认 80，越界整数在读取与修改时夹到 8–80。客户端设置不会扩大服务器授予的技能范围，也不改变技能维护消耗。

实机验证入口：`tools/vfxgraph-editor/scripts/mine-detect-settings.init.gradle`，使用上述独立测试存档，输出到 `build/mine-detect-settings-validation/`。
